## Phase Details

### Phase 23: Runtime Capability Contract

**Goal:** Align the resource-kind capability model with actual Claude Code and Codex runtime semantics.

**Requirements:** RTS-01, RTS-02, RTS-03, RTS-04, SIMPLE-01, SIMPLE-02, SIMPLE-03

**Success Criteria:**
1. Claude command assets render only to `.claude/commands/<id>.md`.
2. Codex command targets are rejected with clear validation/apply diagnostics and never create `.codex/commands/*`.
3. Simple assets continue to render directly without workflow files.
4. Simple assets cannot declare or imply argument handling.
5. Runtime capability status and setup UI capability labels match the real support matrix.

**Plans:**
- Wave 1: [23-01 Shared capability and validation contract](phases/23-runtime-capability-contract/23-01-PLAN.md) — complete
- Wave 2: [23-02 Apply/render hard gate and BDD coverage](phases/23-runtime-capability-contract/23-02-PLAN.md) — complete

**Verification:** [23-VERIFICATION.md](phases/23-runtime-capability-contract/23-VERIFICATION.md)

**Cross-cutting constraints:**
- Codex command assets are validation errors, never warnings or mapped Codex skills.
- Simple assets remain workflow-free and cannot support arguments.
- Apply must fail before writing generated output when config validation fails.

### Phase 24: Workflow Asset Model (Completed)

**Goal:** Add first-class optional workflow assets for shared process instructions used by runtime-specific wrappers.

**Requirements:** WF-01, WF-02, WF-03, WF-04

**Verification:** [24-VERIFICATION.md](phases/24-workflow-asset-model/24-VERIFICATION.md)

**Success Criteria:**
1. `.aof` config can declare workflow assets with explicit runtime targets.
2. Workflow files render to runtime-specific generated workflow locations.
3. Claude command wrappers and Codex skill wrappers can reference the same workflow.
4. Workflow-backed argument metadata renders appropriately for Claude and Codex wrappers.
5. Simple assets remain workflow-free by default.

**Plans:**
- Wave 1: [24-01 Workflow config model and validation foundation](phases/24-workflow-asset-model/24-01-PLAN.md)
- Wave 2: [24-02 Workflow rendering and wrapper defaults](phases/24-workflow-asset-model/24-02-PLAN.md)
- Wave 3: [24-03 Workflow API compatibility, BDD, and docs](phases/24-workflow-asset-model/24-03-PLAN.md)

**Cross-cutting constraints:**
- Workflows are top-level config entries with source files at `.aof/assets/workflows/<id>/WORKFLOW.md`.
- Generated workflow files live under `.claude/aof/workflows/` and `.codex/aof/workflows/`.
- Wrappers bind to workflows with `workflow: "<id>"`; explicit wrapper body wins, absent body gets a generated default.
- Project and global workflows are in Phase 24 scope.
- `{{skills.*}}` and `{{workflows.*}}` placeholders remain Phase 25; setup UI mode controls remain Phase 26.

### Phase 25: Asset Reference Placeholders (Completed)

**Goal:** Add validated runtime-aware references for skills and workflows.

**Requirements:** REF-01, REF-02, REF-03, REF-04

**Success Criteria:**
1. `{{skills.<id>}}` expands to the correct runtime skill path.
2. `{{workflows.<id>}}` expands to the correct runtime workflow path.
3. Validation fails for missing referenced assets.
4. Validation fails for references to assets that do not target the current runtime.
5. Runtime overrides and global references participate in reference resolution.

**Plans:**
- Wave 1: [25-01 Reference parser and rendering](phases/25-asset-reference-placeholders/25-01-PLAN.md) — complete
- Wave 2: [25-02 Validation and global references](phases/25-asset-reference-placeholders/25-02-PLAN.md) — complete
- Wave 3: [25-03 BDD, PowerShell parity, and docs](phases/25-asset-reference-placeholders/25-03-PLAN.md) — complete

**Verification:** [25-VERIFICATION.md](phases/25-asset-reference-placeholders/25-VERIFICATION.md)

### Phase 26: Workflow-Backed Setup UI (Completed)

**Goal:** Update the setup UI so users can intentionally choose simple or workflow-backed authoring.

**Requirements:** UI-01, UI-02, UI-03, UI-04

**Success Criteria:**
1. Asset creation/editing exposes Simple and Workflow-backed modes.
2. Argument fields are hidden for simple assets and available for workflow-backed assets.
3. Codex is disabled as a runtime option for command assets with explanatory copy.
4. The UI can insert `{{skills.*}}` and `{{workflows.*}}` references from known project/global assets.
5. UI save validation returns structured diagnostics for invalid modes, arguments, and references.

**Plans:**
- Wave 1: [26-01 Editable workflow-backed resource model](phases/26-workflow-backed-setup-ui/26-01-PLAN.md) — complete
- Wave 2: [26-02 Resource editor controls](phases/26-workflow-backed-setup-ui/26-02-PLAN.md) — complete
- Wave 3: [26-03 BDD and docs](phases/26-workflow-backed-setup-ui/26-03-PLAN.md) — complete

**Verification:** [26-VERIFICATION.md](phases/26-workflow-backed-setup-ui/26-VERIFICATION.md)

### Phase 27: Workflow Runtime Verification (Completed)

**Goal:** Harden the new runtime semantics with BDD, docs, and live UAT against GSD-style examples.

**Requirements:** HARD-01, HARD-02, HARD-03, HARD-04, HARD-05

**Success Criteria:**
1. Node BDD covers Codex command rejection, Claude-only command rendering, valid references, and invalid references.
2. PowerShell BDD parity covers the new runtime/workflow scenarios.
3. Live UAT verifies a Claude command wrapper and Codex skill wrapper sharing a workflow file.
4. README and CLI help explain simple vs workflow-backed assets, argument support, and Codex command rejection.
5. `npm run test:unit`, `npm test`, `npm run test:integration:ps`, and UI build checks pass where relevant.

**Plans:**
