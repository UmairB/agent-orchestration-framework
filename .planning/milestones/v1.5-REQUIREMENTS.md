# Requirements: AOF

**Defined:** 2026-05-11
**Milestone:** v1.5 Runtime Semantics And Workflow Assets
**Core Value:** Users can configure assistant skills, commands, agents, rules/instructions, workflows, and GSD framework setup once in `.aof/`, then reliably generate the correct Claude Code and Codex files without hand-maintaining assistant-specific folders.

## v1.5 Requirements

### Runtime Semantics

- [x] **RTS-01**: User can rely on AOF to render Claude command assets only to Claude command files.
- [x] **RTS-02**: User is prevented from targeting Codex with command assets because Codex does not support commands.
- [x] **RTS-03**: User sees clear validation and apply-time diagnostics when an asset requests a runtime that cannot represent that asset kind.
- [x] **RTS-04**: User can still target Codex explicitly with skill assets when they want Codex behavior.

### Simple Asset Authoring

- [x] **SIMPLE-01**: User can continue authoring simple skills, commands, agents, and rules without workflow files.
- [x] **SIMPLE-02**: User cannot configure arguments for simple assets.
- [x] **SIMPLE-03**: User receives validation guidance when simple asset content appears to depend on argument placeholders or argument frontmatter.

### Workflow Assets

- [x] **WF-01**: User can define a first-class workflow asset that contains shared process instructions.
- [x] **WF-02**: User can render workflow assets into runtime-specific generated workflow locations for Claude and Codex.
- [x] **WF-03**: User can attach workflow-backed runtime wrappers, such as a Claude command wrapper and a Codex skill wrapper, to the same shared workflow.
- [x] **WF-04**: User can configure workflow-backed arguments once and have AOF render runtime-appropriate argument metadata and wrapper body guidance.

### Asset References

- [x] **REF-01**: User can reference another skill with `{{skills.<id>}}` and have AOF render the correct runtime path.
- [x] **REF-02**: User can reference a workflow with `{{workflows.<id>}}` and have AOF render the correct runtime path.
- [x] **REF-03**: User receives validation errors when a referenced skill or workflow does not exist.
- [x] **REF-04**: User receives validation errors when a referenced skill or workflow does not target the runtime where the reference is used.

### Setup UI

- [x] **UI-01**: User can choose between Simple asset and Workflow-backed asset authoring in the setup UI.
- [x] **UI-02**: User sees argument fields only for workflow-backed assets.
- [x] **UI-03**: User cannot select Codex as a runtime for command assets in the setup UI.
- [x] **UI-04**: User can insert supported `{{skills.*}}` and `{{workflows.*}}` references from the setup UI without memorizing exact syntax.

### Verification And Hardening

- [x] **HARD-01**: BDD scenarios cover Codex command rejection and Claude-only command rendering.
- [x] **HARD-02**: BDD scenarios cover workflow-backed Claude command and Codex skill wrappers that reference the same workflow.
- [x] **HARD-03**: BDD scenarios cover valid and invalid `{{skills.*}}` and `{{workflows.*}}` references.
- [x] **HARD-04**: Live UAT verifies behavior against a GSD-style command/skill/workflow example.
- [x] **HARD-05**: README and CLI help explain simple vs workflow-backed assets and runtime command support accurately.

## Future Requirements

### Catalog And Distribution

- **CAT-01**: User can discover or install assets from a hosted or local catalog after the catalog product path is redesigned.
- **DIST-01**: User can publish, synchronize, or vendor global assets across machines.

### Runtime Expansion

- **RTME-01**: User can target additional assistant runtimes beyond Claude Code and Codex.

### UI Execution

- **UIX-01**: User can execute init/apply/package operations from the UI after local execution safety and confirmation semantics are designed.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Mapping AOF commands into Codex skills | User explicitly rejected this because it makes command-vs-skill authoring ambiguous. |
| Requiring workflows for every asset | Simple assets should remain lightweight and direct. |
| Runtime support beyond Claude Code and Codex | This milestone fixes known semantics for the current concrete runtimes. |
| Hosted registry/discovery | Runtime semantics and workflow modeling come first. |
| UI-driven apply/install execution | UI remains a source editor; command execution remains in CLI for this milestone. |
