# Phase 19 Wave 3 Plan: Assets Namespace Help Docs And Parity Hardening

## Objective

Harden the completed assets namespace migration with product-area help, docs, removed-command parity, Node/PowerShell BDD coverage, and phase completion artifacts.

## Planning Assumptions

- Waves 1 and 2 implement the command behavior.
- This wave is allowed to adjust prior implementation details only where verification exposes gaps.
- Phase 19 must leave package and project namespace work for Phases 20 and 21, but removed old asset commands must not remain executable.

## Requirements Covered

- **ASSET-01..ASSET-06:** Full assets namespace behavior is verified and documented.

## Decisions Covered

- **D-01..D-16:** Full migration, full asset command set, no legacy aliases, preserved render/lock/drift/global-ref behavior, and no old UI launch.

## Tasks

1. Replace help text with the accepted assets namespace surface.
   - Group help by product area.
   - Show `aof init` under project setup.
   - Show `aof assets add`, `add --global`, `list`, `show`, `remove`, `use`, `unuse`, `apply`, `validate`, `clean`, and `ui`.
   - Keep package/project commands either as coming next or included only if already implemented by later phases; do not advertise old executable commands.
   - Include workflow examples for new project, reusable global asset, and applying assets.

2. Standardize removed-command error messages.
   - Old asset-related commands should use one helper for replacement guidance.
   - `add` suggests `aof assets add skill`.
   - `global` suggests `aof assets add --global skill`, `assets list --global`, and `assets use --global skill <id>`.
   - `apply` and `sync` suggest `aof assets apply`.
   - `clean` suggests `aof assets clean`.
   - `install` suggests `aof assets ui` for the editor and notes package install moved to `aof packages install` in Phase 20.
   - Error paths must avoid importing modules that can create catalog/SQLite side effects.

3. Align README with Phase 19 behavior.
   - Replace old `aof add`, `aof global`, `aof apply`, `aof sync`, `aof clean`, and `aof install` examples with namespaced assets commands.
   - Document `aof assets apply` defaulting to configured runtimes.
   - Document `aof assets ui` as the editor launcher.
   - Keep package namespace examples minimal or marked as upcoming if Phase 20 has not run yet.

4. Complete Node BDD parity.
   - Ensure every ASSET requirement has at least one scenario.
   - Ensure removed old asset commands are tested as failures with no side effects.
   - Ensure old command strings no longer appear as successful command examples.
   - Preserve existing non-asset scenarios where Phase 20/21 will handle command migration later.

5. Complete PowerShell parity.
   - Update `test/integration/cli.ps1` command expectations and helper behavior for namespaced assets.
   - Cover at least: `assets add`, `assets add --global`, `assets use --global`, `assets apply --dry-run`, `assets validate --global`, `assets clean --dry-run`, and removed command failures.

6. Run final phase verification and fix concrete gaps.
   - Run unit tests, Node BDD, PowerShell BDD, UI build, and CLI smoke checks.
   - Fix only issues directly tied to Phase 19 behavior.
   - Do not implement packages namespace or project namespace behavior beyond replacement hints.

7. Update planning artifacts after successful verification.
   - Mark ASSET-01 through ASSET-06 complete in `.planning/REQUIREMENTS.md`.
   - Update `.planning/ROADMAP.md` Phase 19 status, wave statuses, and v1.4 progress.
   - Update `.planning/STATE.md` to advance to Phase 20 discussion.
   - Update `.planning/MILESTONES.md` v1.4 progress.

## Acceptance Criteria

- `aof --help` does not advertise old asset top-level commands as working commands.
- README namespaced asset examples match shipped behavior.
- Node and PowerShell BDD pass with namespaced assets scenarios.
- No old asset-related top-level command executes or causes side effects.
- ASSET-01 through ASSET-06 are covered by passing tests and marked complete.
