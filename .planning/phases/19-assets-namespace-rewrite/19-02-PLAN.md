# Phase 19 Wave 2 Plan: Assets Apply Validate Clean And UI

## Objective

Move rendering, asset validation, lock-owned cleanup, and local editor launch into the assets namespace while preserving existing behavior and removing catalog-backed UI launch.

## Planning Assumptions

- Wave 1 has established `aof assets` routing and old source command failures.
- `aof assets apply` replaces old asset rendering from both `aof apply` and the asset-rendering portion of `aof sync`.
- Package installer execution is not part of this phase; package namespace work is Phase 20.
- The setup UI remains a source configuration editor and must not execute apply/install.

## Requirements Covered

- **ASSET-03:** Render configured assets to all configured project runtimes with `aof assets apply`, with runtime flags narrowing a single run.
- **ASSET-04:** Validate asset configuration and referenced globals with `aof assets validate`.
- **ASSET-05:** Open the source asset editor through `aof assets ui`; no install command launches the editor.
- **ASSET-06:** Clean lock-owned generated asset outputs through the assets namespace with drift protection preserved.

## Decisions Covered

- **D-08..D-11:** `assets apply` and `assets clean` preserve rendering, lock, warnings, global refs, associated files, and drift behavior.
- **D-12..D-14:** `assets ui` is the only editor launch command and must not use catalog-backed setup UI launch.
- **D-15..D-16:** Old render/cleanup/UI top-level commands fail without side effects.

## Tasks

1. Implement `aof assets apply`.
   - Reuse existing render planning, adapter warning, strict-mode, lock-writing, and drift-protection behavior.
   - Default to runtimes configured in `.aof/aof.config.json`.
   - Let `--codex`, `--claude`, or `--runtime codex,claude` narrow the current run.
   - Preserve `--dry-run`, `--json`, `--strict`, `--force`, `--target`, and `--config`.
   - Ensure dry-run output states no files or lock state were written.
   - Do not run package installers or network commands.

2. Implement `aof assets validate`.
   - Project scope validates asset source configuration and referenced global assets using existing project validation.
   - `--global` validates the global asset library.
   - Preserve `--json` and `--strict`.
   - Include adapter warnings for project scope where existing validation does.
   - Keep diagnostics focused on assets and referenced globals; package namespace validation belongs to Phase 20.

3. Implement `aof assets clean`.
   - Reuse existing `createCleanPlan` and `executeCleanPlan`.
   - Preserve lock-owned cleanup and drift preservation.
   - Preserve `--dry-run`; ensure dry-run states no generated files or lock entries were removed.
   - Do not delete source assets.

4. Implement `aof assets ui`.
   - Move editor launch from old `install` behavior to `assets ui`.
   - Print a useful local editor message: URL, project path, terminal lifetime, and `Press Ctrl+C`.
   - Stop using `openCatalog()` to launch the UI.
   - Adjust `serveSetupUi` or its callers so project/global source editing APIs still work without a catalog object.
   - Remove or isolate `/api/items` catalog routes from the launch path so `assets ui` creates no SQLite/catalog side effects.
   - Preserve correct static MIME types for Vite/module scripts.

5. Disable old render/cleanup/UI command execution.
   - `aof apply`, `aof sync`, `aof clean`, and `aof install` fail with namespaced replacement hints.
   - `aof sync` should not execute asset rendering or package installers.
   - `aof install` should not launch UI or package installers; Phase 20 owns package replacement.
   - Failures must not create `.aof`, lock, runtime output, catalog, or SQLite files.

6. Update BDD coverage.
   - Rewrite old `apply` scenarios to `assets apply`.
   - Rewrite old `sync --dry-run` asset-rendering scenarios to `assets apply --dry-run`.
   - Rewrite old `validate` asset/global scenarios to `assets validate`.
   - Rewrite old `clean` scenarios to `assets clean`.
   - Add `assets ui --port 4177` launch-output coverage.
   - Add removed command scenarios for `apply`, `sync`, `clean`, and `install`.
   - Keep package installer scenarios for Phase 20 pending or explicitly mark them as removed-command failures if they execute old `install`.

## Acceptance Criteria

- `aof assets apply --dry-run` previews configured project runtimes by default.
- Runtime flags narrow an apply run.
- `aof assets validate --global` validates the global library.
- `aof assets clean --dry-run` preserves generated files and lock entries.
- `aof assets ui --port 4177` starts the local editor without SQLite/catalog initialization.
- Old `apply`, `sync`, `clean`, and `install` commands fail helpfully and do not execute.
