# Phase 19 Wave 1 Plan: Assets Source Command Namespace

## Objective

Implement the source-management portion of `aof assets ...`: project/global asset creation, listing, inspection, removal, and project references to global assets.

## Planning Assumptions

- This is a full migration. Old `aof add` and `aof global ...` command routes must not keep executing.
- Reuse existing source asset scaffolding and setup UI reference helpers where possible.
- Global assets remain stored in `~/.aof` or `AOF_GLOBAL_HOME` during tests.
- Source removal must not remove generated `.codex` or `.claude` output.

## Requirements Covered

- **ASSET-01:** Project asset creation through `aof assets add skill|command|rule|agent`, including partial interactive forms.
- **ASSET-02:** Global asset create, inspect, validate, and reference operations through the assets namespace.

## Decisions Covered

- **D-01..D-04:** Full assets migration, no staged compatibility, full accepted assets command set.
- **D-05..D-07:** Project/global add and global reference commands.
- **D-15..D-16:** Old asset source commands fail with guidance and no side effects.

## Tasks

1. Add assets namespace routing in `src/cli.mjs`.
   - Route `aof assets add`, `list`, `show`, `remove`, `use`, and `unuse`.
   - Parse `--global` as a scope flag inside `assets`.
   - Reject unknown `assets` subcommands with usage examples.
   - Keep `aof init` top-level; do not move init in this plan.

2. Move project asset creation to `aof assets add`.
   - Preserve direct forms such as `aof assets add skill code-review --codex --description "Review code"`.
   - Preserve partial interactive forms such as `aof assets add` and `aof assets add skill`.
   - In partial `aof assets add skill`, keep kind fixed and prompt only for missing values.
   - Preserve `--name`, `--description`, `--runtime`, `--claude`, `--codex`, `--force`, `--dry-run`, and `--target`.
   - Update success output to mention `aof assets ui` or direct file editing, not `aof install`.

3. Move global asset creation to `aof assets add --global`.
   - Support global `skill`, `agent`, and `rule`.
   - Reject global `command` with a direct message matching existing global-scope constraints.
   - Preserve existing global workspace path resolution and `AOF_GLOBAL_HOME` test override.
   - Ensure global adds do not create project `.aof` state.

4. Implement asset list and show commands.
   - `aof assets list` lists project-local assets from current project config.
   - `aof assets list --global` lists global assets from global config.
   - `aof assets show <kind> <id>` shows project-local metadata and file presence.
   - `aof assets show --global <kind> <id>` preserves existing global show behavior under the new namespace.
   - Support `--json` for list/show using stable shapes.

5. Implement asset removal.
   - `aof assets remove <kind> <id>` removes the source asset metadata and source files from project `.aof`.
   - `aof assets remove --global <kind> <id>` removes global source metadata and global source files.
   - Support `--dry-run` and `--force`.
   - Refuse to remove generated runtime outputs; point users to `aof assets clean`.
   - Preserve unrelated config sections such as `packages`, `mcpServers`, `hooks`, `projectDocs`, `settings`, and `globalRefs`.

6. Implement global reference commands.
   - `aof assets use --global <kind> <id>` adds a `globalRefs` entry through existing validation.
   - `aof assets unuse --global <kind> <id>` removes the project reference only.
   - Validate missing global assets, duplicate refs, and local/global conflicts through existing diagnostics.
   - Ensure `unuse` never deletes global source files.

7. Disable old source command execution.
   - `aof add` fails with a helpful `aof assets add ...` replacement.
   - `aof global` fails with a helpful `aof assets ... --global` replacement.
   - These failures must not write `.aof`, global config, source files, locks, catalog files, or runtime outputs.

8. Add/update BDD coverage.
   - Cover full and partial `assets add` for project assets.
   - Cover `assets add --global`, `assets list`, `assets show`, `assets use --global`, and `assets unuse --global`.
   - Cover `assets remove` dry-run and actual source removal.
   - Cover removed `add` and `global` commands as non-executing failures.
   - Keep deterministic prompt input via existing test environment variables.

## Acceptance Criteria

- `aof assets add skill code-review --codex --description "Review code"` creates `.aof/assets/skills/code-review/SKILL.md`.
- `aof assets add skill` prompts for missing asset fields without asking for kind.
- `aof assets add --global skill shared-review --codex` writes only to the global AOF workspace.
- `aof assets use --global skill shared-review` updates project `globalRefs`; `unuse` removes only that reference.
- `aof assets remove` deletes source metadata/files only, not generated outputs.
- Old `aof add` and `aof global` fail with replacement hints and no side effects.
