# Phase 24 Wave 2 Plan: Workflow Rendering And Wrapper Defaults

<objective>
Render project and referenced global workflows into AOF-owned runtime workflow paths, then render workflow-backed Claude command and Codex skill wrappers with deterministic default bodies when explicit wrapper bodies are absent.
</objective>

<context>
Read before execution:
- `.planning/phases/24-workflow-asset-model/24-CONTEXT.md`
- `.planning/phases/24-workflow-asset-model/24-RESEARCH.md`
- `.planning/phases/24-workflow-asset-model/24-01-PLAN.md`
</context>

<tasks>

1. **Render workflow files to runtime AOF namespaces.**
   - Type: code
   - Files: `src/adapters.mjs`
   - Action:
     - Add workflow output generation for each requested runtime.
     - Use output paths:
       - `.claude/aof/workflows/<id>.md`
       - `.codex/aof/workflows/<id>.md`
     - Include frontmatter or a generated comment consistent with AOF outputs.
     - Preserve workflow body content from local or referenced global source.
     - Include source metadata with `kind: "workflow"`, id, scope, and global metadata where relevant.
   - Verify:
     - Unit tests assert project workflows render to both runtime paths.
     - Unit tests assert runtime filtering honors workflow `runtimes`.
   - Acceptance criteria:
     - WF-02 workflow output paths are generated and lock-trackable.

2. **Generate default workflow-backed wrapper bodies.**
   - Type: code
   - Files: `src/adapters.mjs`
   - Action:
     - When a resource has `workflow` and no explicit body/prompt/instructions, generate default wrapper content.
     - Generated content must reference the resolved runtime workflow path directly.
     - Claude command default should be command-appropriate and include argument hint/metadata when present.
     - Codex skill default should be skill-appropriate and include argument guidance in the body.
     - Explicit wrapper body must win unchanged, except for existing supported associated-file placeholder behavior.
   - Verify:
     - Unit tests cover generated Claude command default body.
     - Unit tests cover generated Codex skill default body.
     - Unit tests cover explicit wrapper body winning.
   - Acceptance criteria:
     - WF-03 wrappers can share one workflow.
     - WF-04 argument metadata renders into runtime-facing wrapper guidance.

3. **Preserve wrapper runtime semantics.**
   - Type: code
   - Files: `src/adapters.mjs`
   - Action:
     - Keep Phase 23 Codex command rejection intact.
     - Ensure Codex wrapper examples use `kind: "skill"`, not `kind: "command"`.
     - Ensure simple non-workflow resources render as before.
   - Verify:
     - Existing Phase 23 render guard tests still pass.
     - Add regression tests for a workflow-backed Codex skill and Claude command sharing a workflow.
   - Acceptance criteria:
     - No `.codex/commands/*` output is introduced.

4. **Integrate workflow outputs with render planning and cleanup.**
   - Type: code
   - Files: `src/render-plan.mjs`, `src/lock.mjs` if needed
   - Action:
     - Confirm workflow outputs flow through `createRenderPlan()`, `planApplyActions()`, and `createLockManifest()` without special-case drift bypasses.
     - Add stale workflow cleanup tests where a previously lock-owned `.claude/aof/workflows/<id>.md` is deleted when no longer desired.
     - Add drift protection tests for modified stale workflow files.
   - Verify:
     - Render-plan unit tests cover create/update/delete/drift behavior for workflow outputs.
   - Acceptance criteria:
     - Workflow generated files get the same lock safety as resources.

5. **Protect output conflict behavior.**
   - Type: code
   - Files: `src/adapters.mjs`, `test/render-plan.test.mjs`
   - Action:
     - Ensure local and global workflow ID conflicts are caught in validation before render.
     - Ensure duplicate generated workflow paths fail predictably if validation is bypassed.
   - Verify:
     - Unit tests cover conflict or rely on validation test from Wave 1 plus a defensive render-plan conflict test.
   - Acceptance criteria:
     - Rendering cannot silently merge unrelated workflow bodies.

</tasks>
