# Phase 24 Wave 3 Plan: Workflow API Compatibility, BDD, And Docs

<objective>
Expose workflow assets through existing config editing paths where needed, prove the user-visible workflow model through Node and PowerShell BDD, and document the Phase 24 contract without implementing Phase 25 placeholders or Phase 26 workflow-mode UI.
</objective>

<context>
Read before execution:
- `.planning/phases/24-workflow-asset-model/24-CONTEXT.md`
- `.planning/phases/24-workflow-asset-model/24-RESEARCH.md`
- `.planning/phases/24-workflow-asset-model/24-01-PLAN.md`
- `.planning/phases/24-workflow-asset-model/24-02-PLAN.md`
</context>

<tasks>

1. **Keep setup/config editor APIs workflow-compatible.**
   - Type: code
   - Files: `src/config-editor.mjs`, `src/setup-ui.mjs`
   - Action:
     - Include `workflows` in editable config load payloads.
     - Preserve workflows when saving editable sections or resources.
     - Allow project/global references to workflow assets through existing global-ref API if that API is generic enough; otherwise add minimal support for `kind: "workflow"`.
     - Ensure setup UI validation surfaces workflow diagnostics from `validateConfig()` / `validateGlobalConfig()`.
     - Do not build full Simple vs Workflow-backed UI controls; defer that to Phase 26.
   - Verify:
     - Config-editor/setup UI tests cover workflow preservation and diagnostics.
   - Acceptance criteria:
     - UI APIs do not delete or corrupt workflows.
     - Workflow validation errors are returned structurally.

2. **Update workspace writer/test fixture helpers.**
   - Type: code
   - Files: `src/workspace-writer.mjs`, test fixture helpers
   - Action:
     - Ensure workspace writing helpers can create workflow source files and top-level `workflows`.
     - Preserve `workflows` in config writing where these helpers generate `.aof/aof.config.json`.
     - Update Node integration shared steps with workflow fixtures:
       - project workflow
       - missing workflow wrapper
       - runtime mismatch wrapper
       - invalid argument override
       - referenced global workflow
   - Verify:
     - Unit/helper tests or BDD fixture usage proves helpers write the expected files.
   - Acceptance criteria:
     - BDD fixtures can express the Phase 24 workflow model without ad hoc setup duplication.

3. **Add Node BDD scenarios for workflow model behavior.**
   - Type: test
   - Files: `test/integration/features/lifecycle.feature`, `test/integration/steps/shared-cli.steps.mjs`
   - Action:
     - Add scenarios for:
       - rendering project workflow files to `.claude/aof/workflows/<id>.md` and `.codex/aof/workflows/<id>.md`
       - rendering Claude command and Codex skill wrappers that share one workflow
       - rejecting missing workflow references
       - rejecting workflow runtime mismatch
       - rejecting argument override for undeclared workflow argument
       - rendering referenced global workflow with lock/source traceability
     - Assert generated wrapper bodies include resolved runtime workflow paths.
   - Verify:
     - `npm test`
   - Acceptance criteria:
     - Phase 24 user-visible behavior is covered by Node BDD.

4. **Add PowerShell parity.**
   - Type: test
   - Files: `test/integration/cli.ps1`
   - Action:
     - Mirror the new Node BDD fixture steps in the PowerShell runner.
     - Preserve single-runtime array serialization fixes from Phase 23.
     - Add assertions for generated workflow files and validation diagnostics.
   - Verify:
     - `npm run test:integration:ps`
   - Acceptance criteria:
     - Windows parity covers the same workflow scenarios.

5. **Update README and CLI-facing docs.**
   - Type: docs
   - Files: `README.md`
   - Action:
     - Document top-level `workflows`.
     - Document source path `.aof/assets/workflows/<id>/WORKFLOW.md`.
     - Document generated paths `.claude/aof/workflows/<id>.md` and `.codex/aof/workflows/<id>.md`.
     - Document `workflow: "<id>"` wrapper binding.
     - Document argument metadata as rendering guidance only.
     - Explicitly state that `{{skills.*}}` and `{{workflows.*}}` placeholders are Phase 25 and not part of Phase 24 unless implemented later.
   - Verify:
     - README examples match tested config fixtures.
   - Acceptance criteria:
     - Users can understand simple assets versus workflow-backed wrappers from docs.

6. **Run phase verification and close planning gaps.**
   - Type: verification
   - Files: tests and planning artifacts as needed
   - Action:
     - Run the verification commands below.
     - Fix failures caused by Phase 24 changes.
     - Confirm WF-01 through WF-04 are covered by implementation and tests.
   - Verify:
     - `npm run test:unit`
     - `npm test`
     - `npm run test:integration:ps`
   - Acceptance criteria:
     - All Phase 24 requirements are covered by tests or explicit docs.

</tasks>
