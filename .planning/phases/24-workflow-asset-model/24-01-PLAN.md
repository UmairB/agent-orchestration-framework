# Phase 24 Wave 1 Plan: Workflow Config Model And Validation Foundation

<objective>
Add first-class workflow declarations to the AOF model and validation layer, including project and global workflow references, workflow-backed wrapper binding, and argument metadata validation.
</objective>

<context>
Read before execution:
- `.planning/phases/24-workflow-asset-model/24-CONTEXT.md`
- `.planning/phases/24-workflow-asset-model/24-RESEARCH.md`
- `.planning/phases/23-runtime-capability-contract/23-CONTEXT.md`
- `.planning/REQUIREMENTS.md`
</context>

<tasks>

1. **Add workflow model metadata.**
   - Type: code
   - Files: `src/model.mjs`
   - Action:
     - Add exported workflow metadata for `id: "workflow"`, `plural: "workflows"`, and default body file `WORKFLOW.md`.
     - Add helper exports as needed, such as `supportedGlobalRefKinds()` or `defaultWorkflowBodyFile()`, to avoid hard-coded duplicate kind lists.
     - Keep `RESOURCE_KINDS` unchanged for directly invoked resources unless the implementation clearly benefits from a separate workflow constant.
   - Verify:
     - Add model unit coverage for the workflow body filename and any new helper.
   - Acceptance criteria:
     - Workflow metadata is centrally defined.
     - Existing resource kind and capability tests still pass.

2. **Extend schema for workflows and workflow-backed wrappers.**
   - Type: code
   - Files: `schemas/aof.schema.json`
   - Action:
     - Add top-level `workflows` array referencing a new `$defs.workflow`.
     - Define workflow fields: `id`, `name`, `description`, `runtimes`, `body`, `path`, `argumentHint`, and `arguments`.
     - Define simple named arguments with `name`, optional `description`, and optional `required`.
     - Add resource fields `workflow`, `argumentHint`, `arguments`, and `argumentOverrides`.
     - Extend global refs so `kind: "workflow"` is valid.
   - Verify:
     - Update schema alignment tests if they assert top-level sections or enum lists.
   - Acceptance criteria:
     - Valid workflow configs can be represented without schema drift.
     - Existing resource configs remain schema-compatible.

3. **Resolve project and global workflows in DSL loading.**
   - Type: code
   - Files: `src/dsl.mjs`
   - Action:
     - Add `resolveWorkflow()` mirroring resource body resolution, runtime normalization, id normalization, and source path tracking.
     - Include `workflows` in `resolveConfig()` return value.
     - Extend `normalizeGlobalRefs()` to allow workflow refs.
     - Extend `loadProjectConfig()` so project `globalRefs` can merge referenced global workflows into `config.workflows` with `_aofSource.scope = "global"`.
     - Preserve existing global resource behavior.
   - Verify:
     - Unit tests load project-local workflows.
     - Unit tests load referenced global workflows.
   - Acceptance criteria:
     - `loadProjectConfig()` returns local and referenced global workflows.
     - Existing global resource references are not regressed.

4. **Validate workflow declarations.**
   - Type: code
   - Files: `src/config-inspect.mjs`
   - Action:
     - Validate top-level `workflows` is an array when present.
     - Validate each workflow object, `id`, runtimes, body/path, file existence, `argumentHint`, and `arguments`.
     - Validate duplicate local workflow IDs.
     - Validate referenced global workflows only when referenced by project config.
     - Validate local/global workflow ID conflicts.
     - Add stable diagnostic codes for workflow errors.
   - Verify:
     - Add tests for valid workflow, missing workflow file, duplicate workflow ID, malformed arguments, malformed global workflow, and missing referenced global workflow.
   - Acceptance criteria:
     - Invalid workflow configs fail before rendering.
     - Project validation ignores malformed unrelated global workflow drafts.

5. **Validate workflow-backed wrappers.**
   - Type: code
   - Files: `src/config-inspect.mjs`
   - Action:
     - Build a local plus referenced global workflow index during config validation.
     - For any resource with `workflow`, validate the workflow exists.
     - Validate every wrapper effective runtime is included in workflow runtimes.
     - Validate `argumentOverrides` references only declared workflow argument names.
     - Allow argument fields on resources only when `workflow` is set; keep Phase 23 simple asset rejection for resources without `workflow`.
   - Verify:
     - Add tests for missing workflow, runtime mismatch, invalid override argument, and valid Claude command plus Codex skill sharing a workflow.
   - Acceptance criteria:
     - Workflow-backed wrappers can carry argument metadata.
     - Simple assets still reject argument metadata and argument markers.

</tasks>
