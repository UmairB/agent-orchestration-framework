# Phase 21 Wave 1 Plan: Project Command Namespace

## Objective

Implement the accepted `aof project ...` namespace for project inspection, validation, diagnostics, and legacy root-config migration while preserving existing behavior under the new names.

## Planning Assumptions

- This is a full migration. Old top-level project/config commands are not aliases and will be removed in Wave 2.
- `aof init` remains top-level and must stay source-only: create `.aof` project state, then guide users to namespaced next commands.
- Existing config inspection and doctor semantics are valuable and should be reused rather than rewritten.
- `project` means the current repository's AOF workspace, config, lock state, migration state, and health.

## Requirements Covered

- **PROJ-01:** Initialize a project workspace with top-level `aof init` and no hidden defaults or side effects.
- **PROJ-02:** Inspect, validate, and diagnose project-level AOF configuration through clear project-scoped commands.
- **PROJ-03:** Migrate legacy root config intentionally through the rewritten command surface.

## Decisions Covered

- **D-01..D-02:** Full project namespace migration with no aliases.
- **D-04..D-07:** Keep `aof init` top-level and source-only.
- **D-08..D-12:** Implement `project show`, `validate`, `doctor`, and `migrate` preserving existing semantics.
- **D-13..D-15:** Preserve migration safety, dry-run, force, and root-file untouched output.

## Tasks

1. Add project namespace routing in `src/cli.mjs`.
   - Route `aof project show`.
   - Route `aof project validate`.
   - Route `aof project doctor`.
   - Route `aof project migrate`.
   - Reject unknown project subcommands with concrete examples.

2. Implement `aof project show`.
   - Reuse existing config inspection logic.
   - Preserve `--json`, `--target`, and `--config`.
   - Human output should show config path, project name, runtimes, resources, global references, packages, and relevant warnings.
   - JSON output should remain automation-friendly and stable with the existing inspection payload shape unless a targeted rename is necessary.

3. Implement `aof project validate`.
   - Reuse existing whole-project validation logic.
   - Preserve `--json`, `--strict`, `--target`, `--config`, and runtime narrowing where adapter warnings are runtime-specific.
   - Preserve global-reference, associated-file, package, adapter-warning, and strict-mode diagnostics.
   - Keep failure exit behavior for validation errors and strict warning failures.

4. Implement `aof project doctor`.
   - Reuse existing project doctor logic.
   - Preserve `--json`, `--strict`, `--target`, and runtime narrowing where relevant.
   - Preserve stale legacy config warnings, generated-output drift summaries, missing file checks, package intent checks, adapter warnings, and next-command suggestions.
   - Update suggestions to use `aof assets ...`, `aof packages ...`, and `aof project ...`.

5. Implement `aof project migrate [dir]`.
   - Move the existing migration command body behind the project namespace.
   - Preserve legacy root config source detection.
   - Preserve `.aof/aof.config.json` and `.aof/aof.lock.json` writes.
   - Preserve `--dry-run` and `--force`.
   - Output source path, destination config path, lock path, and that the root config was left untouched.

6. Tighten `aof init` next-step output.
   - Ensure init creates only `.aof/aof.config.json` and `.aof/aof.lock.json`.
   - Ensure no prompt asks to create assets during init.
   - Ensure no package, UI, render, catalog, or SQLite behavior is reachable.
   - Ensure legacy root config guidance says `aof project migrate`.
   - Ensure next steps include:
     - `aof assets add ...`
     - `aof packages add gsd`
     - `aof assets apply --dry-run`
     - `aof project validate`

7. Add/update BDD coverage.
   - Add project show human and JSON scenarios.
   - Add project validate success, validation failure, strict adapter warning failure, and JSON scenarios.
   - Add project doctor health, stale legacy config, package intent, and strict adapter warning scenarios.
   - Add project migrate success, dry-run, force, and failure scenarios.
   - Add init source-only assertions if missing.

## Acceptance Criteria

- `aof project show` replaces the useful behavior of `aof config show`.
- `aof project validate` replaces the useful behavior of top-level `validate`.
- `aof project doctor` replaces the useful behavior of top-level `doctor` and `config doctor`.
- `aof project migrate` replaces the useful behavior of top-level `migrate`.
- `aof init` remains the only top-level product command and does not create assets, launch UI, render outputs, install packages, or touch catalog storage.
