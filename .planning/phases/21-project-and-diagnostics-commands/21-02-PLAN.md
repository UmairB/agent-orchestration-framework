# Phase 21 Wave 2 Plan: Removed Project Config And Catalog Paths

## Objective

Remove old project/config/catalog execution paths so the rewritten CLI has one authoritative surface: `aof project ...` for project health and migration, and no active catalog product path.

## Planning Assumptions

- Wave 1 has already implemented the project namespace replacements.
- Removed commands may print helpful replacement guidance, but they must not execute old behavior.
- Catalog/SQLite behavior is intentionally out of product scope until redesigned.
- This wave must be careful about side effects: removed commands should fail before reading or writing project config, lock, runtime outputs, package attempts, catalog files, or SQLite-backed storage.

## Requirements Covered

- **PROJ-02:** Project diagnostics have clear project-scoped names.
- **PROJ-03:** Legacy migration is reachable only through the project namespace.
- **PROJ-04:** Active SQLite/catalog behavior is absent from the user-visible CLI.

## Decisions Covered

- **D-01..D-03:** Full migration with no executable aliases.
- **D-16..D-17:** Removed project/config commands fail with targeted no-side-effect guidance.
- **D-18..D-20:** Catalog remains removed and has no SQLite/catalog-storage side effects.

## Tasks

1. Remove top-level execution routes.
   - `aof validate` must fail and point to `aof project validate` and, where helpful, `aof assets validate`.
   - `aof doctor` must fail and point to `aof project doctor`.
   - `aof migrate` must fail and point to `aof project migrate`.
   - Ensure these routes do not execute validation, diagnostics, or migration logic.

2. Remove config namespace execution.
   - `aof config show` must fail and point to `aof project show`.
   - `aof config validate` must fail and point to `aof project validate`.
   - `aof config doctor` must fail and point to `aof project doctor`.
   - `aof config` and unknown config subcommands should fail with concise namespace guidance.
   - Ensure config removed-command failures do not inspect the project or read config files.

3. Remove catalog command execution.
   - `aof catalog`, `aof catalog path`, `aof catalog init`, and `aof catalog list` must fail with deliberate unsupported-product-path guidance.
   - Error output should explain that project/global `.aof` assets are the active source model.
   - Error output should point to relevant source commands, such as `aof assets add skill`, `aof assets add --global skill`, and `aof assets list --global`.
   - Ensure catalog commands do not import `node:sqlite`, open catalog storage, seed defaults, or create data files.

4. Audit catalog/SQLite imports on active CLI paths.
   - Confirm `src/cli.mjs` no longer imports catalog modules for active command routing.
   - Confirm `aof init`, `aof assets ui`, removed-command errors, and help output do not trigger SQLite warnings.
   - If `src/catalog.mjs` remains for deferred tests or future product work, ensure it is not reachable from active CLI command execution.

5. Update removed-command BDD coverage.
   - Add assertions that `validate`, `doctor`, `migrate`, and `config ...` fail with replacement guidance and no side effects.
   - Add assertions that catalog commands fail without creating catalog DB files.
   - Add assertions that removed commands do not create `.aof`, runtime output, or lock files when run in an empty project unless the scenario intentionally starts with an initialized project.

6. Update Node child-process smoke for removed paths.
   - Smoke `node bin/aof.mjs validate`.
   - Smoke `node bin/aof.mjs doctor`.
   - Smoke `node bin/aof.mjs migrate`.
   - Smoke `node bin/aof.mjs config show`.
   - Smoke `node bin/aof.mjs catalog list`.
   - Confirm stderr guidance and no SQLite experimental warning text.

## Acceptance Criteria

- Removed top-level `validate`, `doctor`, and `migrate` commands do not execute.
- Removed `config ...` commands do not execute.
- Removed `catalog ...` commands do not initialize catalog storage or import SQLite behavior.
- Every removed command gives a targeted replacement or unsupported-product-path message.
- BDD proves removed commands are failures, not aliases.
