# Phase 21 Wave 3 Plan: Project Namespace Help Docs And Parity Hardening

## Objective

Harden the completed project namespace migration with help text, README updates, Node/PowerShell BDD parity, smoke coverage, and phase completion artifacts.

## Planning Assumptions

- Waves 1 and 2 implement project namespace commands and remove old config/diagnostics/catalog execution paths.
- This wave may adjust implementation details only where verification exposes concrete gaps.
- Phase 22 owns live-repository verification; this phase should make the command surface internally consistent and test-covered before that live test.

## Requirements Covered

- **PROJ-01..PROJ-04:** Full project namespace behavior is verified and documented.

## Decisions Covered

- **D-01..D-20:** Full project namespace migration, top-level init boundary, removed command behavior, and no active catalog/SQLite product path.

## Tasks

1. Align CLI help with the final v1.4 command surface.
   - Keep top-level help limited to `aof init`.
   - Add or update a `Project:` help section:
     - `aof project show`
     - `aof project validate`
     - `aof project doctor`
     - `aof project migrate [dir]`
   - Keep `Assets:` and `Packages:` help from Phases 19 and 20.
   - Remove help entries for top-level `migrate`, top-level `validate`, top-level `doctor`, `config`, and `catalog`.
   - Ensure defaults text describes project scope and namespaced next commands.

2. Standardize replacement and unsupported messages.
   - `validate` should point to `aof project validate`.
   - `doctor` should point to `aof project doctor`.
   - `migrate` should point to `aof project migrate`.
   - `config show|validate|doctor` should point to `aof project show|validate|doctor`.
   - `catalog` should state catalog is not currently supported and point to project/global asset commands.
   - Unknown command guidance should include `aof assets ...`, `aof packages ...`, and `aof project ...` examples.

3. Align README with the project namespace.
   - Replace `aof migrate` examples with `aof project migrate`.
   - Replace `aof validate` examples with `aof project validate` or `aof assets validate` depending on scope.
   - Replace `aof doctor` and `aof config doctor` examples with `aof project doctor`.
   - Replace `aof config show` examples with `aof project show`.
   - Remove catalog command documentation except deferred/future notes if needed.
   - Explain that `project` means the current repository's AOF workspace and health.

4. Complete BDD parity.
   - Ensure Node BDD covers every PROJ requirement.
   - Ensure PowerShell parity covers at least:
     - `init --codex` source-only behavior.
     - `project show`.
     - `project validate`.
     - `project doctor`.
     - `project migrate`.
     - removed `validate`, `doctor`, `migrate`, `config`, and `catalog` failures.
   - Keep scenarios black-box and command-contract focused.

5. Update child-process smoke checks.
   - Include project namespace smoke commands:
     - `project show`
     - `project validate`
     - `project doctor`
     - `project migrate --dry-run`
   - Include removed command smoke with no SQLite warning assertions.
   - Ensure smoke does not depend on user/global state.

6. Run final phase verification and fix concrete gaps.
   - Run unit tests, Node BDD, PowerShell BDD, UI build if docs/help-only changes do not make it unnecessary, child-process smoke, and aggregate check.
   - Fix only issues directly tied to Phase 21 behavior.

7. Update planning artifacts after successful verification.
   - Mark PROJ-01 through PROJ-04 complete in `.planning/REQUIREMENTS.md`.
   - Update `.planning/ROADMAP.md` Phase 21 status, wave statuses, and v1.4 progress.
   - Update `.planning/STATE.md` to advance to Phase 22 discussion.
   - Update `.planning/MILESTONES.md` v1.4 progress.

## Acceptance Criteria

- `aof --help` documents `init`, `assets`, `packages`, and `project`, and does not advertise removed project/config/catalog commands.
- README examples match shipped project namespace behavior.
- Node and PowerShell BDD pass with project namespace scenarios.
- Removed project/config/catalog commands fail without executing or producing SQLite warnings.
- PROJ-01 through PROJ-04 are covered by passing tests and marked complete.
