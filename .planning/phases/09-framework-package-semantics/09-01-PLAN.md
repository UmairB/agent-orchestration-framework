# Phase 9 Wave 1 Plan: Package Descriptor Normalization And Validation

## Objective

Add a shared package model that accepts current string sources and structured npm/git/file descriptors, requires explicit namespaces, and normalizes direct dependency metadata before downstream install, render, or lock code sees package data.

## Planning Assumptions

- Existing string source support remains valid, but package declarations must now include an explicit `namespace`.
- GSD remains the concrete framework package, but source descriptor support should not be hard-coded to npm-only.
- Validation errors should use the existing config diagnostic shape.
- This wave does not fetch packages, run installers, or write generated outputs.

## Requirements Covered

- **PKG-01:** Adds consistent descriptors for npm, git, and local file package sources.
- **PKG-02:** Requires namespaces before any package can participate in output planning.
- **PKG-03:** Normalizes direct dependency metadata for later lock recording.

## Tasks

1. Add a shared package model module.
   - Create `src/packages.mjs`.
   - Export `normalizePackage()`, `normalizePackages()`, `normalizePackageSource()`, `normalizePackageDependencies()`, and `packageInstallSpec()`.
   - Keep helpers pure and side-effect-free.
   - Include stable package source types: `npm`, `git`, and `file`.

2. Normalize string sources.
   - Accept `source: "npm:get-shit-done-cc@latest"`.
   - Accept `source: "git:https://example.test/pkg.git#v1.0.0"`.
   - Accept `source: "file:../packages/pkg"`.
   - Normalize each to a structured source object with `type`, `requested`, `installSpec`, and source-specific fields.
   - Preserve exact source text for diagnostics and lock readability.

3. Normalize structured sources.
   - Accept npm objects with package/name plus version/tag/range.
   - Accept git objects with url and optional ref.
   - Accept file objects with path.
   - Resolve local file paths against the config directory for validation metadata while retaining a readable project/config-relative path.
   - Reject unsupported source types with actionable diagnostics.

4. Require explicit namespaces.
   - Add namespace validation to `validatePackage()`.
   - Use the same conservative id pattern as resources.
   - Reject missing, empty, or invalid namespace values.
   - Update the CLI default config and test package fixtures to include `"namespace": "gsd"`.

5. Normalize direct dependencies.
   - Support `dependencies` and architecture-compatible `depends_on` input, normalizing both to one internal `dependencies` array.
   - Require dependency `id` or `name`.
   - Allow version/range/ref metadata as plain strings.
   - Preserve `optional: true` where provided.
   - Detect duplicate direct dependencies within a package and report validation errors.

6. Wire normalization into config loading.
   - Update `resolveConfig()` so `packages` is returned normalized.
   - Ensure existing callers that read `config.packages` still receive `id`, `namespace`, `source`, and `runtimes`.
   - Keep normalized data backward-compatible enough for current framework install planning until Wave 2 updates that path.

7. Update schema and user-facing validation tests.
   - Update `schemas/aof.schema.json` for namespace, string-or-object source descriptors, and dependency arrays.
   - Add unit coverage for valid npm/git/file string and object descriptors.
   - Add unit coverage for missing namespace, invalid namespace, unsupported source type, duplicate dependency, and invalid runtimes.
   - Add BDD coverage that `validate` accepts npm/git/file package descriptors and rejects missing namespace.

## Acceptance Criteria

- `loadConfig()` returns normalized package entries for string and structured source forms.
- `validateConfig()` accepts npm, git, and local file package descriptors.
- Package `namespace` is required and validated.
- Direct dependency metadata is normalized but not expanded into a transitive graph.
- Current GSD fixtures and default config are updated to include `namespace: "gsd"`.
