# Phase 9 Wave 3 Plan: Package Output Claims And Conflict Gates

## Objective

Apply package namespaces to package-owned emitted files before write planning, then fail before any side effect when packages or local primitives claim the same generated output path outside known safe merge cases.

## Planning Assumptions

- Package-owned output claims should reuse the existing desired-output planning path.
- The current Codex `AGENTS.md` rule merge remains a safe exception.
- Conflict failures are pre-write gates and must happen before lock mutation or installer execution.
- No implicit local-over-package priority or package priority override is introduced in Phase 9.

## Requirements Covered

- **PKG-02:** Package namespaces are applied to emitted files before writes.
- **PKG-04:** Conflicting generated output claims fail before side effects and identify involved packages/local primitives.

## Tasks

1. Add package output ownership metadata.
   - Extend package normalization or add helpers so package-provided primitives can be represented as package-owned sources.
   - Preserve package id, namespace, source type, and original primitive kind/id in the source metadata.
   - Use this metadata in diagnostics and lock entries.

2. Apply namespace before rendering package-owned outputs.
   - Prefix package-owned prompt-like resource ids with the package namespace before calling existing adapter rendering.
   - Ensure package skill `code-review` with namespace `gsd` produces final ids/paths such as `gsd-code-review`.
   - Preserve local primitive ids unchanged.
   - Do not namespace runtime fixed files blindly; use existing merge/claim policy for root project docs and runtime config outputs.

3. Improve duplicate output diagnostics.
   - Replace or wrap the generic `Multiple resources render to the same path` error with a structured conflict error.
   - Include final generated path, runtime, and each claimant.
   - Claimants must identify local primitives as `local:<kind>:<id>` and package primitives as `package:<packageId>:<kind>:<id>` with namespace.
   - Keep deterministic claimant ordering for testable output.

4. Enforce pre-write gates in apply and sync.
   - Ensure conflicts thrown during `createRenderPlan()` prevent `planApplyActions()`, `executeApplyActions()`, `writeLock()`, and framework installer execution.
   - Make `apply --dry-run`, `sync --dry-run`, `apply`, and `sync --install` all share the same conflict path.
   - Ensure JSON dry-run failures still exit non-zero and include actionable error text through existing CLI error handling.

5. Preserve known safe merge behavior.
   - Keep deterministic Codex rule merge to `AGENTS.md`.
   - If package-owned Codex rules participate in a safe merge, preserve package ownership in the merged output `sources` metadata.
   - Do not add new silent merges for package project docs or fixed runtime config outputs unless explicitly covered by tests and existing behavior.

6. Add user-facing package conflict tests.
   - Unit test package-owned resources receive namespace prefixes before final paths are grouped.
   - Unit test local/package duplicate output claims fail with both claimants named.
   - Unit test package/package duplicate output claims fail with both package ids named.
   - Unit test safe Codex rule merge still passes and preserves deterministic ordering.
   - BDD test `sync --dry-run` fails before generated files and lock state when package/local claims conflict.
   - BDD test `sync --install` does not run installers when output conflicts exist.

7. Document the package policy.
   - Update README package section with source descriptors, required namespace, direct dependencies, lock metadata, and conflict behavior.
   - Include one valid npm package example with `namespace: "gsd"`.
   - Document that networked installers still require explicit install/sync flags.

## Acceptance Criteria

- Package-owned outputs are namespaced before write planning.
- Duplicate final output claims fail before files, lock state, or installers change anything.
- Conflict messages identify packages and local primitives involved.
- Existing Codex `AGENTS.md` rule merging remains intentional and deterministic.
- README explains package namespace, lock, and conflict behavior.
