# Phase 7 Wave 1 Plan: Expanded DSL Model And Validation

## Objective

Extend the `.aof/aof.config.json` source model so users can declare MCP servers, hooks, project docs, and settings without changing or breaking existing `resources[]` behavior.

## Planning Assumptions

- **A-01:** New primitives use dedicated top-level config sections: `mcpServers`, `hooks`, `projectDocs`, and `settings`.
- **A-02:** Existing `resources[]` remains the model for skills, commands, agents, and rules; no migration is required for v1 configs.
- **A-03:** Phase 7 validates common-core structure and runtime filters now; strict degradation policy is deferred to Phase 8.

## Requirements Covered

- **DSL-01:** Adds MCP server declarations to the normalized config model.
- **DSL-02:** Adds hook declarations to the normalized config model.
- **DSL-03:** Adds project documentation declarations to the normalized config model.
- **DSL-04:** Adds project-level settings with runtime escape hatches.
- **DSL-05:** Preserves existing v1 resources and config compatibility.

## Tasks

1. Add model definitions for expanded primitives.
   - Update `src/model.mjs` with canonical supported hook events, hook handler types, MCP transports, project doc targets, and setting trust modes.
   - Export helper functions for supported primitive ids where useful.
   - Keep `supportedResourceKinds()` unchanged for v1 resource kinds unless a call site explicitly needs the expanded primitive list.

2. Normalize expanded config sections.
   - Update `src/dsl.mjs` so `resolveConfig()` returns `mcpServers`, `hooks`, `projectDocs`, and `settings` in addition to existing `resources` and `packages`.
   - Normalize ids through `normalizeId()`.
   - Normalize runtime lists to default `["claude", "codex"]`.
   - Resolve project doc bodies from `path` using the config directory as the base.
   - Preserve runtime-specific objects under `claude` and `codex` without attempting full degradation policy in this phase.

3. Validate expanded config sections.
   - Update `src/config-inspect.mjs` validation for:
     - MCP server id, transport, stdio command/args/env, HTTP url/headers, runtime filters, and duplicate ids.
     - Hook id, event, matcher shape, handler type, command requirement for common command hooks, runtime filters, and duplicate ids.
     - Project doc id, path/body, targets limited to `AGENTS.md` and `CLAUDE.md`, include path safety, and runtime filters.
     - Settings object shape, vendor-neutral fields, and runtime escape hatch object shape.
   - Keep validation errors machine-readable with precise diagnostic paths.

4. Update JSON schema.
   - Extend `schemas/aof.schema.json` with top-level definitions for `mcpServers`, `hooks`, `projectDocs`, and `settings`.
   - Keep `additionalProperties: true` where runtime escape hatches need forward compatibility.
   - Add enum alignment tests for new shared constants.

5. Add focused unit tests.
   - Create `test/dsl-primitives.test.mjs`.
   - Cover normalization of all new sections.
   - Cover v1 resource configs still resolving unchanged.
   - Cover invalid transport/event/target/runtime diagnostics.
   - Register the new test file in `scripts/test-unit.mjs` and `scripts/test.mjs`.

## Acceptance Criteria

- A config with only existing `resources[]` continues to load and validate.
- A config with valid `mcpServers`, `hooks`, `projectDocs`, and `settings` loads into a normalized object.
- Invalid expanded primitive fields produce targeted diagnostics from `aof validate`.
- Schema enums and model constants stay aligned.
- No runtime output behavior changes yet except passing through the expanded normalized model.
