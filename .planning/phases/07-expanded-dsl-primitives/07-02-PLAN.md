# Phase 7 Wave 2 Plan: Runtime Rendering For MCP Hooks Docs And Settings

## Objective

Render the expanded DSL primitives into Claude Code and Codex project outputs while preserving existing apply/sync dry-run, drift protection, stale pruning, and lock ownership behavior.

## Planning Assumptions

- **A-04:** Runtime config output is generated and lock-owned like current assistant folders; root `AGENTS.md`, `CLAUDE.md`, and `.mcp.json` are protected by existing drift checks.
- **A-05:** Common-core hooks in Phase 7 are command hooks only. Rich prompt, agent, HTTP, and MCP-tool-specific hook policy is handled by runtime escape hatches and Phase 8 degradation work.

## Requirements Covered

- **DSL-01:** MCP declarations render to Claude `.mcp.json` and Codex `.codex/config.toml`.
- **DSL-02:** Common command hooks render to Claude `.claude/settings.json` and Codex `.codex/config.toml`.
- **DSL-03:** Project docs render deterministically to root `AGENTS.md` and `CLAUDE.md`.
- **DSL-04:** Settings render to runtime-specific project config files with vendor-neutral defaults and pass-through escape hatches.
- **DSL-05:** Existing skills, commands, agents, and rules still render unchanged.

## Tasks

1. Add deterministic runtime config helpers.
   - Create `src/runtime-config.mjs` for pure helpers that build JSON/TOML strings.
   - Implement a minimal deterministic TOML serializer for the subset AOF emits: strings, booleans, numbers, arrays, nested tables, and arrays of tables.
   - Keep key ordering stable for golden-style assertions.

2. Render MCP servers.
   - Add Claude output at root `.mcp.json` with `mcpServers`.
   - Add Codex output at `.codex/config.toml` with `[mcp_servers.<id>]` tables.
   - Support stdio fields: `command`, `args`, `env`.
   - Support HTTP fields: `url`, `headers`.
   - Pass Codex-specific fields such as `supports_parallel_tool_calls`, `default_tools_approval_mode`, and per-tool approval overrides only to Codex.
   - Pass Claude-specific fields only to Claude.

3. Render hooks.
   - Merge generated hooks into `.claude/settings.json` under `hooks`.
   - Merge generated hooks into `.codex/config.toml` under `[hooks.<Event>]` arrays of matcher groups.
   - Support common command hook shape: `event`, optional `matcher`, `type: "command"`, and `command`.
   - Preserve runtime-specific hook extensions only for the matching runtime.
   - Keep unsupported rich hook behavior out of Phase 7 unless the runtime-specific extension is explicitly targeted.

4. Render project docs.
   - Generate root `AGENTS.md` for Codex-targeted docs.
   - Generate root `CLAUDE.md` for Claude-targeted docs.
   - Add an explicit include macro such as `{{include path/to/file.md}}`.
   - Resolve includes relative to the source doc file.
   - Guard against missing include files, recursive include cycles, and path traversal.
   - Use deterministic section ordering when multiple project docs target the same file.

5. Render settings.
   - Map vendor-neutral settings only where there is a safe direct target.
   - Merge `settings.claude` into `.claude/settings.json`.
   - Merge `settings.codex` into `.codex/config.toml`.
   - Do not silently invent runtime mappings for ambiguous settings; leave them as runtime-specific escape hatches or defer to Phase 8 warning policy.

6. Preserve render-plan behavior.
   - Ensure generated runtime config/doc outputs flow through existing `createRenderPlan()`, `planApplyActions()`, `executeApplyActions()`, and lock manifest creation.
   - Extend grouping behavior only where multiple project docs intentionally compose into the same target.
   - Keep drifted root docs/config files protected unless `--force` is used through existing behavior.

7. Add BDD and unit coverage.
   - BDD: applying MCP config creates `.mcp.json` and `.codex/config.toml`.
   - BDD: applying hooks creates runtime settings/config outputs.
   - BDD: project docs render to `AGENTS.md` and `CLAUDE.md` with include expansion.
   - BDD: existing v1 resource render scenarios still pass unchanged.
   - Unit: TOML serializer and doc include expansion are deterministic.

## Acceptance Criteria

- `aof apply --dry-run` previews expanded primitive outputs without writing.
- `aof apply` and `aof sync` write expanded primitive outputs and lock entries.
- Drifted generated root docs/config files are preserved by default.
- Existing resource rendering and lock behavior remain unchanged.
- MCP, hooks, docs, and settings all have user-facing integration coverage.
