# Phase 13 Wave 2 Plan: Associated File Rendering And Lock Ownership

## Objective

Render associated files for skill resources into runtime skill directories and route them through existing render-plan conflict detection, drift protection, writes, and lock state.

## Planning Assumptions

- Wave 1 validates `files` and resolves source asset directories.
- Associated files are text/code/helper files and can use existing text hashing/writing.
- Skills are directory-shaped for Claude and Codex.
- Associated files should work for referenced global skills and may also work for local skills through the same safe path.

## Requirements Covered

- **CODE-02:** Rendering preserves associated files for runtime asset shapes that require directories, such as skills with helper scripts.
- **CODE-03:** Render planning prevents associated files from overwriting unrelated generated output.

## Decisions Covered

- **D-05:** Render associated files for skills.
- **D-07:** Local skills may share the same code path if safe.
- **D-11:** Render planning detects associated-file output conflicts before writes.
- **D-12:** Associated files render into the runtime skill directory preserving relative path.
- **D-13:** Associated file outputs participate in create/update/delete/drift protection and lock state.
- **D-14:** Lock metadata identifies associated files as outputs from the owning resource and preserves global source scope.
- **D-15:** Dry-run output shows associated file actions through existing action formatting.

## Tasks

1. Add associated-file output generation.
   - Extend `src/adapters.mjs` to emit extra desired outputs for skill resources with `files`.
   - Render each associated file under the same runtime skill directory as `SKILL.md`.
   - Preserve relative subdirectories.
   - Use source metadata from `src/dsl.mjs` to read associated file contents from the owning asset directory.

2. Add output metadata.
   - Mark associated file outputs with resource metadata that identifies the owner resource.
   - Include an indicator such as `artifact: "associated-file"` or `file: <relative path>` in `output.resource`.
   - Preserve `scope: "global"` and global source details for referenced global skills.
   - Preserve package metadata behavior.

3. Reuse render-plan behavior.
   - Ensure associated file outputs are included before `groupDesiredOutputs()`.
   - Let path-based conflict detection catch helper files colliding with markdown outputs or other helper files.
   - Ensure `executeApplyActions()` writes associated files through the same path as generated markdown.
   - Ensure `createLockManifest()` persists associated-file lock entries.

4. Add render-plan tests.
   - Associated files render under `.codex/skills/<id>/...`.
   - Associated file lock entries include owner/source metadata.
   - Dry-run/planning returns create actions for associated files.
   - Drifted associated files produce drift warnings.
   - Associated-file output conflicts fail before writes.

5. Verify wave 2.
   - Run `npm run test:unit`.

## Acceptance Criteria

- Skill associated files render into runtime skill directories for selected runtimes.
- Associated files are tracked in lock state.
- Associated files use the existing create/update/delete/drift planning behavior.
- Output conflicts involving associated files fail before writes.
- Global source scope is preserved on associated-file lock entries.
