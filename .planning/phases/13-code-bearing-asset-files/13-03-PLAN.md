# Phase 13 Wave 3 Plan: Associated File BDD Docs And Phase Hardening

## Objective

Prove the user-facing global skill helper-file workflow, document the manifest syntax and safety rules, and close out Phase 13 planning state.

## Planning Assumptions

- Wave 2 renders associated files through apply/sync and lock state.
- BDD coverage should use a referenced global skill because global code-bearing assets are the core Phase 13 value.
- UI changes are not part of Phase 13.

## Requirements Covered

- **CODE-01:** Global assets can own associated files under their asset directory.
- **CODE-02:** Rendering preserves associated files for runtime skill directories.
- **CODE-03:** Validation rejects unsafe associated files and output conflicts.

## Decisions Covered

- **D-01:** Associated files use explicit `files` entries.
- **D-05:** Phase 13 supports skills.
- **D-08:** Unsafe paths are validation errors.
- **D-11:** Render planning prevents output conflicts.
- **D-13:** Associated files participate in drift/lock behavior.
- **D-14:** Lock metadata preserves global source scope.

## Tasks

1. Add BDD scenario for referenced global skill helper files.
   - Create a global skill with `files: ["scripts/search.py"]`.
   - Reference it from a project through `globalRefs`.
   - Run `aof apply --codex`.
   - Assert `.codex/skills/<id>/scripts/search.py` exists and contains expected content.
   - Assert project `.aof/assets` does not receive copied global helper files.
   - Assert `.aof/aof.lock.json` records the helper output with global source scope.

2. Add BDD scenario for unsafe associated files.
   - Create a global skill with a path escape or missing associated file.
   - Reference it from a project.
   - Run `aof validate`.
   - Assert the command fails with clear associated-file diagnostics.

3. Add BDD scenario for dry-run/sync behavior if not already covered by unit tests.
   - Run `aof sync --codex --dry-run` on a project with referenced global skill helper files.
   - Assert planned create output mentions the helper file.
   - Assert no helper file is written in dry-run.

4. Update README.
   - Document the `files` array on skill resources.
   - Show a global skill example with a helper script.
   - State that paths are relative to the asset directory and cannot escape it.
   - State that Phase 13 supports skill helper files; other resource kinds are deferred.

5. Run full Phase 13 verification.
   - Run `npm run test:unit`.
   - Run `npm test`.
   - `npm run ui:build` is not required unless UI files change unexpectedly.

6. Update completion artifacts.
   - Write `.planning/phases/13-code-bearing-asset-files/13-03-SUMMARY.md`.
   - Write `.planning/phases/13-code-bearing-asset-files/13-VERIFICATION.md`.
   - Update roadmap, requirements traceability, project state, and project summary after execution.

## Acceptance Criteria

- BDD proves a referenced global skill renders helper files into runtime skill directories.
- BDD proves unsafe associated files fail validation.
- README documents syntax, safety constraints, and Phase 13 scope.
- Phase state advances to Phase 14 after execution.
- Unit and BDD verification pass.
