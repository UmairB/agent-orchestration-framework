# Phase 13 Wave 1 Plan: Associated File Model And Validation

## Objective

Add explicit associated-file metadata for asset-owned helper/code files and validate the paths safely before any rendering changes write them.

## Planning Assumptions

- Associated files are declared on resources through `files`.
- `files` entries are relative to the asset directory containing the primary body file.
- Phase 13 renders associated files for skills only.
- Validation should apply to project-local resources and referenced global resources through the same project validation boundary.

## Requirements Covered

- **CODE-01:** Global assets can own associated files under their asset directory.
- **CODE-03:** Validation rejects associated files that escape the asset directory.

## Decisions Covered

- **D-01:** Associated files are explicit in the manifest through `files`.
- **D-02:** Each entry is relative to the asset directory.
- **D-03:** Do not infer associated files by scanning.
- **D-04:** Primary body and override files are not associated files.
- **D-05:** Render support starts with skill resources.
- **D-06:** Agents, rules, and commands are deferred.
- **D-08:** Paths must be relative, contained, and not target the primary body file.
- **D-09:** Entries must resolve to regular files.
- **D-10:** Symlinks must be rejected or resolved safely.

## Tasks

1. Extend schema and normalized resource model.
   - Add `files` to resource schema as an array of strings.
   - Carry normalized `files` through `resolveResource()` in `src/dsl.mjs`.
   - Attach enough source-path metadata to resolved resources to find the asset directory during rendering.
   - Preserve existing behavior when `files` is absent.

2. Validate associated-file shape.
   - In `src/config-inspect.mjs`, ensure `files` is an array of non-empty strings when present.
   - Reject `files` on non-skill resources for Phase 13.
   - Reject resources that declare `files` without a `path`, because the asset directory is ambiguous.
   - Reject primary body file duplication.

3. Validate associated-file paths.
   - Resolve entries relative to the asset directory.
   - Reject absolute paths.
   - Reject `..` escapes and any path resolving outside the asset directory.
   - Reject missing paths.
   - Reject directories.
   - Reject or safely resolve symlinks so the real target cannot escape the asset directory.

4. Preserve project-scoped global validation.
   - Ensure referenced global resources validate associated files.
   - Ensure unreferenced malformed global assets still do not fail project validation.
   - Keep `aof global validate` as whole-library validation.

5. Add focused unit tests.
   - Valid global skill with helper files passes validation.
   - Missing associated file fails validation.
   - Path escape fails validation.
   - Directory associated file fails validation.
   - Symlink escape fails validation where supported by the platform.
   - Non-skill resource with `files` fails validation.
   - Unreferenced global associated-file errors do not fail unrelated project validation.

6. Verify wave 1.
   - Run `npm run test:unit`.

## Acceptance Criteria

- `files` is accepted for skill resources and rejected for unsupported resource kinds.
- Associated files are validated relative to the asset directory.
- Escapes, missing files, directories, and unsafe symlinks produce structured diagnostics.
- Referenced global assets validate associated files without scanning unrelated global drafts.
