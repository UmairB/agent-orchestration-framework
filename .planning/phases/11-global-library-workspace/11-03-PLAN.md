# Phase 11 Wave 3 Plan: Global Validation And Phase Hardening

## Objective

Complete Phase 11 by adding whole-library global validation, tightening schema/test/docs coverage, and proving the global workspace behavior through unit and BDD verification.

## Planning Assumptions

- Wave 2 adds `aof global add`, `list`, and `show`.
- Project references to global assets are not implemented in Phase 11.
- Project validation should not inspect or fail unrelated global assets in this phase.
- `aof global validate` is the whole-library validation command.

## Requirements Covered

- **GLIB-01:** Re-validates global library access through the validation command.
- **GLIB-02:** Ensures created global assets are valid.
- **GLIB-03:** Ensures list/show surfaces remain consistent with diagnostics.
- **GLIB-04:** User receives clear validation errors when a global asset is malformed or missing required files.

## Decisions Covered

- **D-04:** Use explicit `aof global ...` commands.
- **D-06:** Include `aof global validate`.
- **D-07:** `~/.aof/aof.config.json` is canonical.
- **D-08:** Do not infer the authoritative library purely from files.
- **D-10:** Project validation fails only for referenced malformed global assets.
- **D-11:** `aof global validate` validates the whole global library.
- **D-12:** Unrelated broken drafts in `~/.aof` do not block unrelated project validation.

## Tasks

1. Add global validation internals.
   - Add a config-inspection entry point that validates the global workspace config directly.
   - Reuse existing `validateConfig` logic where possible by passing an explicit config path or workspace root.
   - Return structured diagnostics with the same fields as project validation: severity, path, message, and code.
   - Treat missing global config as an empty valid library only if that matches `global list`; otherwise emit a clear "global library not initialized" diagnostic and keep command output actionable.

2. Add `aof global validate`.
   - Route through the explicit `global` command namespace in `src/cli.mjs`.
   - Support human output consistent with `aof validate`.
   - Support `--json` with stable `valid`, `errors`, and `warnings` style fields.
   - Support `--strict` only if warning states exist; do not invent warnings solely for strict mode.
   - Ensure malformed JSON and missing file-backed assets report clearly.

3. Preserve project-validation boundary.
   - Confirm regular `aof validate` does not scan the whole global workspace.
   - Add a unit or BDD regression proving an unrelated malformed global asset does not fail a project that does not reference it.
   - Leave referenced-global validation for Phase 12.

4. Update schema/docs where needed.
   - If the existing schema already validates global `aof.config.json`, document that the same schema applies.
   - If global-only constraints are code-level rather than schema-level, keep schema changes minimal.
   - Update `README.md` with concise examples for `aof global add`, `aof global list`, `aof global show`, and `aof global validate`.
   - Explicitly state that `aof global ...` manages source assets in `~/.aof`, while `--global` on runtime commands still means runtime-global output.

5. Add validation tests.
   - Extend `test/config-inspect.test.mjs` for global config validation and missing file diagnostics.
   - Extend `test/schema.test.mjs` only if schema behavior changes.
   - Extend BDD lifecycle scenarios for `aof global validate` success and failure.
   - Ensure all tests use a fake home/global workspace and never touch real `~/.aof`.

6. Run full Phase 11 verification.
   - Run `npm run test:unit`.
   - Run `npm test`.
   - Run any focused command manually if needed to inspect human output.

7. Update Phase 11 completion state.
   - Ensure all `GLIB-*` requirements are covered by summaries and verification output.
   - Write `.planning/phases/11-global-library-workspace/11-03-SUMMARY.md`.

## Acceptance Criteria

- `aof global validate` validates the whole global library manifest and file-backed assets.
- Malformed global config and missing global asset files produce clear diagnostics.
- Regular project validation remains scoped and does not fail because of unrelated malformed global drafts.
- README documents the Phase 11 global command surface.
- Unit and BDD verification pass.
