# Phase 11 Wave 1 Plan: Global Workspace Path And Manifest Foundation

## Objective

Add the global AOF source workspace foundation so code can locate `~/.aof`, treat it as a mirrored AOF workspace, and keep it distinct from OS app-data catalog storage.

## Planning Assumptions

- `~/.aof` is source-of-truth storage for reusable global AOF assets, not generated Claude/Codex output and not catalog app data.
- The global workspace mirrors the project `.aof` shape: `aof.config.json`, `aof.lock.json` if ever needed later, and `assets/`.
- This plan does not add global project references or runtime rendering.

## Requirements Covered

- **GLIB-01:** User can initialize or access a global AOF library at `~/.aof`.

## Decisions Covered

- **D-01:** `~/.aof` mirrors the project workspace shape.
- **D-02:** Global source workspace includes `~/.aof/aof.config.json` and `~/.aof/assets/<kind>/<id>/...`.
- **D-03:** Reuse project workspace conventions where practical.
- **D-07:** `~/.aof/aof.config.json` is the canonical global asset manifest.

## Tasks

1. Add a global source workspace path helper.
   - Extend `src/paths.mjs` with a helper such as `defaultGlobalWorkspaceDir(env, platform, homedir)` or `defaultAofHome(...)`.
   - Return `path.join(homedir, ".aof")` by default.
   - Keep this separate from `defaultDataDir()` and `defaultDbPath()`.
   - If an override is useful for tests, use an explicit AOF-global-home environment variable and document its purpose in code/tests.

2. Add mirrored workspace path construction.
   - Extend `src/workspace.mjs` with a helper such as `globalWorkspacePaths(options)` or `workspacePathsForRoot(root)`.
   - Return `workspaceDir`, `configPath`, `lockPath`, and `assetsDir` for the global workspace.
   - Preserve existing `workspacePaths(projectDir)` behavior for project workspaces.
   - Avoid changing legacy config behavior for project workspaces.

3. Add global manifest initialization semantics.
   - Provide a small helper that returns an empty global config shape when `~/.aof/aof.config.json` does not exist.
   - Use a global library name such as `"global"` or `"aof-global"` consistently.
   - Use `$schema` in a way that does not break from a home-directory config location; if the current relative schema path is not appropriate, prefer preserving validation over adding a fragile path.

4. Add focused unit tests.
   - Extend `test/paths.test.mjs` for `~/.aof` resolution.
   - Extend `test/workspace.test.mjs` for global workspace path shape.
   - Assert the global source workspace path is not the OS app-data catalog path.
   - Keep existing path tests passing.

5. Verify the foundation.
   - Run `npm run test:unit`.

## Acceptance Criteria

- A reusable helper resolves the global source workspace to `~/.aof`.
- Global workspace paths mirror project `.aof` conventions.
- Catalog app-data paths remain unchanged.
- Unit tests cover the new global path behavior.

## Verification

- `npm run test:unit`
