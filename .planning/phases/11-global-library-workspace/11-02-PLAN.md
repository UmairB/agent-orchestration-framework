# Phase 11 Wave 2 Plan: Global CLI Asset Operations

## Objective

Add explicit `aof global ...` commands that create, list, and inspect global skills, agents, and rules from the canonical `~/.aof/aof.config.json` manifest.

## Planning Assumptions

- Wave 1 provides a helper for locating the global source workspace.
- The documented command path is `aof global ...`, not `--global` on existing source commands.
- Commands should preserve existing CLI output style and avoid changing project-local `aof add` behavior.
- Phase 11 global assets are limited to skills, agents, and rules.

## Requirements Covered

- **GLIB-02:** User can create global skills, agents, and rules in `~/.aof`.
- **GLIB-03:** User can list and inspect global assets independently from project-local assets.

## Decisions Covered

- **D-03:** Reuse project workspace conventions where practical.
- **D-04:** Use explicit `aof global ...` commands.
- **D-05:** Do not overload existing `--global` runtime-output semantics.
- **D-06:** Include command families such as `aof global add`, `aof global list`, and `aof global validate`.
- **D-07:** `~/.aof/aof.config.json` is the canonical global asset manifest.
- **D-08:** Do not infer the authoritative global library purely from scanning files.
- **D-09:** Keep metadata, runtimes, overrides, and validation explicit through the manifest.

## Tasks

1. Refactor asset scaffolding for workspace reuse.
   - Update `src/scaffold.mjs` so the core file-backed resource creation can target either a project workspace or the global workspace.
   - Preserve existing `scaffoldResource(projectDir, input)` behavior for `aof add`.
   - Add a global wrapper such as `scaffoldGlobalResource(input, options)` that targets the global workspace.
   - Restrict global scaffold kinds to `skill`, `agent`, and `rule` for this phase.
   - Preserve collision behavior: existing config resource or asset file fails unless `--force` is supplied.

2. Add `aof global add`.
   - Extend `src/cli.mjs` dispatch with a top-level `global` command namespace.
   - Implement `aof global add <kind> <id> [--runtime claude,codex] [--description text] [--force] [--dry-run]`.
   - Write assets under `~/.aof/assets/<kind-plural>/<id>/<BODY.md>`.
   - Write or update `~/.aof/aof.config.json`.
   - Print `Created ...` and `Updated ...` messages consistent with `aof add`.
   - In dry-run, print planned config and asset writes without writing files.

3. Add `aof global list`.
   - Read `~/.aof/aof.config.json` as canonical.
   - Print global resources as `kind:id` with runtime information where available.
   - Support `--json` if straightforward using the same payload shape as config inspection resources.
   - If no global config exists, report an empty global library rather than failing with a stack trace.

4. Add `aof global show`.
   - Implement a narrow inspection command such as `aof global show <kind> <id>`.
   - Show source path, runtimes, description/name if present, and whether the body file exists.
   - Support `--json` if consistent with `global list`.
   - Fail clearly when the asset is not registered in `~/.aof/aof.config.json`.

5. Update help text and user-facing docs.
   - Add `aof global <add|list|show|validate>` to `helpText()` in `src/cli.mjs`.
   - Mention that `aof global ...` manages source assets in `~/.aof`.
   - Do not change `apply --global`, `sync --global`, or `install --global` meanings.

6. Add BDD lifecycle coverage.
   - Extend `test/integration/features/lifecycle.feature` with scenarios for global add/list/show.
   - Use existing shared CLI step support if possible.
   - Ensure tests isolate the global home with an environment variable or temp home so they do not write to the real user `~/.aof`.
   - Assert files are created under the fake global workspace and project `.aof` remains untouched.

7. Verify global CLI operations.
   - Run `npm run test:unit`.
   - Run `npm test`.

## Acceptance Criteria

- `aof global add` creates global skills, agents, and rules in the mirrored `~/.aof` workspace.
- `aof global list` lists registered global assets from the global manifest.
- `aof global show` inspects a registered global asset and reports missing assets clearly.
- Existing `aof add` and runtime `--global` behavior are unchanged.
- BDD scenarios cover user-facing global command behavior.
