# Phase 20 Wave 3 Plan: Packages Namespace Help Docs And Parity Hardening

## Objective

Harden the completed packages namespace migration with help text, docs, removed-command parity, Node/PowerShell BDD coverage, smoke checks, and phase completion artifacts.

## Planning Assumptions

- Waves 1 and 2 implement package config intent, inspection, validation, install, and lock replay.
- This wave may adjust implementation details only where verification exposes concrete gaps.
- Project namespace cleanup remains Phase 21; do not remove top-level `validate`, `doctor`, `migrate`, `config`, or `catalog` in this phase except where help/replacement text must mention upcoming project commands.

## Requirements Covered

- **PKG-01..PKG-04:** Full packages namespace behavior is verified and documented.

## Decisions Covered

- **D-01..D-22:** Full packages migration, no legacy aliases, explicit installer safety, GSD as concrete v1 package, and no catalog/discovery behavior.

## Tasks

1. Align CLI help with package commands.
   - Add a `Packages:` help section:
     - `aof packages add gsd`
     - `aof packages list`
     - `aof packages show gsd`
     - `aof packages remove gsd`
     - `aof packages validate`
     - `aof packages install [gsd] [--dry-run]`
     - `aof packages install --from-lock [--dry-run]`
   - Keep `aof assets ...` help from Phase 19.
   - Do not advertise old `aof install ...`.

2. Standardize replacement messages.
   - Old `install` failure should point to:
     - `aof assets ui` for editor launch.
     - `aof packages add gsd`.
     - `aof packages install gsd`.
     - `aof packages install --from-lock`.
   - Old `sync` failure should point to `aof assets apply` and `aof packages install`.
   - `assets apply --install` should point to `aof packages install`.

3. Align README with package namespace behavior.
   - Document package declaration with `aof packages add gsd`.
   - Document installer dry-run and non-dry-run behavior.
   - Document explicit network/package-code boundary output.
   - Document lock replay with `aof packages install --from-lock`.
   - Remove stale old `aof install gsd` examples.

4. Complete BDD parity.
   - Ensure Node BDD covers every PKG requirement.
   - Ensure PowerShell parity covers at least:
     - `packages add gsd`
     - `packages list`
     - `packages show gsd`
     - `packages validate`
     - `packages install gsd --dry-run`
     - simulated `packages install gsd`
     - `packages install --from-lock --dry-run`
     - old `install` failures
   - Keep package scenarios black-box and command-contract focused.

5. Update smoke checks.
   - Update `test/integration/cli-child-process.test.mjs` to include package add/list/show/validate and install dry-run if appropriate.
   - Ensure smoke does not perform real networked package installation.

6. Run final phase verification and fix concrete gaps.
   - Run unit tests, Node BDD, PowerShell BDD, UI build if UI/help changes require it, child-process smoke, and aggregate check.
   - Fix only issues directly tied to Phase 20 behavior.

7. Update planning artifacts after successful verification.
   - Mark PKG-01 through PKG-04 complete in `.planning/REQUIREMENTS.md`.
   - Update `.planning/ROADMAP.md` Phase 20 status, wave statuses, and v1.4 progress.
   - Update `.planning/STATE.md` to advance to Phase 21 discussion.
   - Update `.planning/MILESTONES.md` v1.4 progress.

## Acceptance Criteria

- `aof --help` documents package commands and does not advertise old install commands.
- README package examples match shipped behavior.
- Node and PowerShell BDD pass with packages namespace scenarios.
- No old package-related top-level command executes or causes side effects.
- PKG-01 through PKG-04 are covered by passing tests and marked complete.
