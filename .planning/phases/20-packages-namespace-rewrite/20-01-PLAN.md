# Phase 20 Wave 1 Plan: Packages Intent Command Namespace

## Objective

Implement the config-intent portion of `aof packages ...`: add, list, show, remove, and validate managed package declarations without running installer code.

## Planning Assumptions

- This is a full migration. Old `aof install ...` command routes must not be restored.
- GSD is the concrete v1.4 package with special installer semantics.
- Generic package descriptors can continue to validate and render package lock intent, but this phase does not implement package discovery, download, extraction, or hosted registries.
- Package intent commands write only `.aof/aof.config.json`; they must not create runtime output or package install attempts.

## Requirements Covered

- **PKG-01:** Declare GSD package intent through `aof packages add gsd` without running networked installer code.
- **PKG-03:** Inspect and validate managed package intent through the packages namespace.

## Decisions Covered

- **D-01..D-02:** Full package namespace migration with no aliases.
- **D-04..D-07:** Package add/list/show/remove/validate commands.
- **D-14, D-16:** Runtime flags on package add record runtime targets; runtime-home global install scope is not package source scope.
- **D-20..D-21:** No catalog, discovery, registry, uninstall, or UI execution behavior.

## Tasks

1. Add packages namespace routing in `src/cli.mjs`.
   - Route `aof packages add`, `list`, `show`, `remove`, and `validate`.
   - Reject unknown package subcommands with concrete examples.
   - Do not route through old `installCommand()`.

2. Implement `aof packages add gsd`.
   - Require or default package id `gsd`; reject unsupported package ids with a clear message.
   - Add or update one `packages[]` entry shaped consistently with existing config:
     - `id: "gsd"`
     - `namespace: "gsd"`
     - `source: "npm:get-shit-done-cc@latest"` unless `--source` or `--package` overrides it.
     - `runtimes` from `--codex`, `--claude`, `--runtime`, or project configured runtimes where appropriate.
   - Preserve unrelated config sections and resources.
   - Support `--dry-run` with planned config write output and no file writes.
   - Print success output that states config path changed and next command `aof packages install gsd --dry-run`.
   - Ensure output does not print `network-boundary`, `npx`, or installer execution text.

3. Implement package list and show commands.
   - `aof packages list` lists configured packages with id, namespace, source, runtimes, and whether installer attempts exist in lock state.
   - `aof packages show gsd` shows the configured GSD package intent and last lock attempts if present.
   - Support `--json` for both commands with stable payloads.
   - Return a helpful missing-package message when the requested package is not configured.

4. Implement package removal.
   - `aof packages remove gsd` removes the config package entry only.
   - Support `--dry-run`.
   - Preserve lock state and generated/runtime outputs; explicitly say uninstall/cleanup is not performed.
   - Preserve unrelated config sections.

5. Implement package validation.
   - `aof packages validate` validates the project `packages[]` section using existing package normalization/inspection diagnostics.
   - Preserve `--json` and `--strict` behavior where applicable.
   - Scope output wording to packages, not assets.
   - Do not require package install lock attempts for validity.

6. Add/update BDD coverage.
   - Add `packages add gsd --codex` records intent only.
   - Add dry-run add does not write config.
   - Add `packages list`, `packages show gsd`, and JSON variants where useful.
   - Add `packages validate` success and malformed package descriptor failure.
   - Add `packages remove gsd` and dry-run removal.
   - Ensure no package intent command runs installer code, writes lock attempts, or initializes catalog/SQLite.

## Acceptance Criteria

- `aof packages add gsd --codex` writes a GSD package entry to `.aof/aof.config.json`.
- `aof packages add gsd --dry-run` writes nothing and clearly says no installer code ran.
- `aof packages list` and `aof packages show gsd` expose configured intent.
- `aof packages validate` reports valid/invalid package configuration.
- `aof packages remove gsd` removes config intent only and does not uninstall runtime files or mutate lock attempts.
