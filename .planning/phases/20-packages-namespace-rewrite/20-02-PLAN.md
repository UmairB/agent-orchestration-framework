# Phase 20 Wave 2 Plan: Packages Install And Lock Replay

## Objective

Move installer execution and package install replay into `aof packages install ...`, preserving dry-run safety, explicit network/package-code boundaries, simulated test installs, and lock attempt metadata.

## Planning Assumptions

- Wave 1 has package namespace routing and GSD config intent in place.
- Existing framework installer planning in `src/frameworks.mjs` remains the source of truth for GSD installer command construction.
- Non-dry-run package install may execute external `npx` unless tests provide simulated statuses.
- Package installation mutates lock attempt metadata only; it does not mutate package config.

## Requirements Covered

- **PKG-02:** Install declared GSD package intent through `aof packages install gsd` with explicit network/package-code boundary output.
- **PKG-04:** Replay package install intent from lock state through `aof packages install --from-lock`.

## Decisions Covered

- **D-08..D-13:** Package install, all-package install, lock replay, dry-run safety, network boundaries, and simulated lock attempts.
- **D-14..D-15:** Runtime narrowing and runtime-home global install scope.
- **D-17..D-19:** Old install/sync/assets execution paths remain rejected.

## Tasks

1. Implement `aof packages install gsd`.
   - Load configured package intent when available.
   - Allow explicit `--source` or `--package` overrides using existing installer planning behavior.
   - Use selected runtimes from package config unless runtime flags narrow the run.
   - Preserve `--global` as runtime-home install scope.
   - Preserve `--force` prior-attempt rerun behavior.
   - On missing config, either use explicit command flags or fail with guidance to run `aof packages add gsd`.

2. Implement `aof packages install` with no package id.
   - Install all configured installable packages.
   - For v1.4, only GSD has installer execution semantics.
   - For configured non-GSD packages, report unsupported/no installer rather than guessing.
   - If nothing installable is configured, fail with a helpful `aof packages add gsd` suggestion.

3. Implement dry-run behavior.
   - `aof packages install gsd --dry-run` prints exact planned installer commands.
   - Output states no network or installer commands will run.
   - Dry-run writes no lock state.
   - JSON dry-run returns planned commands and `network: false`.

4. Implement non-dry-run execution.
   - Before each non-skipped command, print:
     - `network-boundary: running <command>`
     - package source
     - runtime
     - scope
     - warning that npm/package code may run
   - Execute through `executeFrameworkInstallPlan()`.
   - Write attempt metadata to `.aof/aof.lock.json` with successes, failures, and skipped attempts.
   - On partial failure, print retry commands and fail the process.

5. Implement `aof packages install --from-lock`.
   - Load `.aof/aof.lock.json`.
   - Use `frameworkPlanFromLock()` or equivalent package replay planner.
   - Preserve `--dry-run`, `--json`, and network boundary behavior.
   - Fail clearly when no lock or no install intent exists.

6. Preserve removed/rejected paths.
   - Keep `aof install gsd` and `aof install --from-lock` removed-command failures.
   - Keep `aof assets apply --install` failure pointing to `aof packages install`.
   - Keep `aof sync --install` failure pointing to explicit assets/packages commands.

7. Add/update BDD coverage.
   - Restore installer dry-run coverage under `packages install gsd --dry-run`.
   - Restore successful simulated install attempt coverage under `packages install gsd`.
   - Restore partial failure and retry coverage under `packages install gsd`.
   - Add `packages install` all-configured behavior.
   - Add `packages install --from-lock --dry-run` replay coverage.
   - Keep old `install` and `sync --install` failure scenarios.

## Acceptance Criteria

- `aof packages install gsd --dry-run` previews `npx get-shit-done-cc@latest ...` without writing lock state.
- `aof packages install gsd` prints network/package-code boundaries and records install attempts.
- Re-running a successful matching install skips unless `--force` is passed.
- Partial installer failures record success/failure attempts and print retry commands.
- `aof packages install --from-lock --dry-run` replays package install intent without old `aof install --from-lock`.
- Old top-level install paths remain non-executing failures.
