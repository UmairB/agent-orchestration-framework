# 40-03 Plan: Error Path UAT + Requirements Close

## Goal

Verify the three sync error paths (missing arg, unbound milestone, mismatched milestone) against a disposable board, append evidence to `40-EVIDENCE.md`, and mark BOARD-02/03/04 complete in `REQUIREMENTS.md`.

## Context

Error path testing must NOT touch the live `coordination` board — that board holds Phase 40's running execution record. A temporary board named `test-attach-uat` is created, used for all three error scenarios, then deleted. This wave depends on Wave 2 completing successfully (board must be in synced state for Phase 41).

## Tasks

### 1. Create disposable test board

```
node bin/aof.mjs boards create test-attach-uat --objective "Error path testing" --title "Test Attach UAT"
```

Capture output. The board should be created with `executionProvider: "gsd"` automatically (because this project has GSD configured). Verify with:

```
node bin/aof.mjs boards show test-attach-uat --json
```

Confirm `gsd.milestone.id` is absent or empty (falsy) — this is what triggers `MILESTONE_NOT_BOUND`.

**Note:** `createBoard` calls `ensureAofBoardMilestoneBridge` as a side effect. Since the bridge skill already exists, this is a no-op.

### 2. Test MILESTONE_MISSING_ARG (human form)

```
node bin/aof.mjs boards sync test-attach-uat
```

Expected: non-zero exit, human error output referencing missing `--milestone` argument.

### 3. Test MILESTONE_MISSING_ARG (JSON form)

```
node bin/aof.mjs boards sync test-attach-uat --json
```

Expected JSON:
```json
{
  "ok": false,
  "code": "MILESTONE_MISSING_ARG",
  "message": "<usage message>",
  "next": "aof boards sync test-attach-uat --milestone <milestone-id>"
}
```

Verify: `ok: false`, `code: "MILESTONE_MISSING_ARG"`, `next` contains the correct sync command hint.

If `code` or `next` is missing, log as a UAT finding (medium severity — JSON error schema incomplete).

### 4. Test MILESTONE_NOT_BOUND (human form)

```
node bin/aof.mjs boards sync test-attach-uat --milestone v1.8
```

Expected: non-zero exit, human error output stating the board is not bound to a milestone and needs `attach` first.

### 5. Test MILESTONE_NOT_BOUND (JSON form)

```
node bin/aof.mjs boards sync test-attach-uat --milestone v1.8 --json
```

Expected JSON:
```json
{
  "ok": false,
  "code": "MILESTONE_NOT_BOUND",
  "message": "Board test-attach-uat is not bound to a GSD milestone id.",
  "next": "aof boards milestone attach test-attach-uat --milestone v1.8 --roadmap <path>"
}
```

Verify: `ok: false`, `code: "MILESTONE_NOT_BOUND"`, `next` contains the attach command hint.

### 6. Attach test board to v1.8 (setup for MILESTONE_ID_MISMATCH)

```
node bin/aof.mjs boards milestone attach test-attach-uat --milestone v1.8 --roadmap .planning/ROADMAP.md
```

This binds the test board to v1.8 so we can trigger a mismatch by requesting v1.9.

### 7. Test MILESTONE_ID_MISMATCH (human form)

```
node bin/aof.mjs boards sync test-attach-uat --milestone v1.9
```

Expected: non-zero exit, human error output stating the board is bound to v1.8, not v1.9.

### 8. Test MILESTONE_ID_MISMATCH (JSON form)

```
node bin/aof.mjs boards sync test-attach-uat --milestone v1.9 --json
```

Expected JSON:
```json
{
  "ok": false,
  "code": "MILESTONE_ID_MISMATCH",
  "message": "Board test-attach-uat is bound to milestone v1.8, not v1.9.",
  "expected": "v1.8",
  "actual": "v1.9",
  "next": "aof boards sync test-attach-uat --milestone v1.8"
}
```

Verify: `ok: false`, `code: "MILESTONE_ID_MISMATCH"`, `expected` and `actual` fields present, `next` corrects to the right milestone.

### 9. Remove disposable test board

```
node bin/aof.mjs boards remove test-attach-uat
```

Confirm the test board directory no longer exists:
```
node bin/aof.mjs boards list
```

Output must show only `coordination` — no `test-attach-uat`.

If `boards remove` does not exist, delete the directory manually:
```
Remove-Item -Recurse -Force .aof/boards/test-attach-uat
```

Either way, confirm `.aof/boards/test-attach-uat/` is gone before committing.
