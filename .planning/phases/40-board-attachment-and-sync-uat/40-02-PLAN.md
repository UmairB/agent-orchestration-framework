# 40-02 Plan: Happy Path — Attach + Re-Sync + Doctor

## Goal

Run the full happy-path attach → sync → doctor sequence on the live `coordination` board, verify the expected state transitions and idempotency guarantees, log the re-attach state-reset behavior as a medium-severity finding, and leave the board in a clean synced state for Phase 41 UI dogfood.

## Context

The `coordination` board is currently `status: "synced"` with `gsd.milestone.id: "v1.8"`. This wave will intentionally re-attach (resetting sync state) then immediately re-sync to restore it. The key verifications are:
- Execution records are untouched by both operations
- Task status and execution state are preserved through re-sync
- Doctor reports healthy after completion
- The missing warning about sync-state reset is logged as `UAT-01` (medium severity)

Wave 1 must be complete before this wave begins — the board must be committed to git so that `git diff` accurately shows what attach/sync actually changes.

## Tasks

### 1. Capture pre-attach state snapshot

Run `git status` and record which board-related files are currently clean. This is the before-state reference.

Note the current values from `BOARD.json`:
- `status: "synced"` (will change to `"ready_to_sync"` after attach)
- `gsd.milestone.status: "synced"` (will change)
- `gsd.milestone.syncedAt` (will be cleared)
- `gsd.milestone.binding.status: "synced"` (will change to `"attached"`)

Note current `executions/phase-39.json` status and `executions/phase-40.json` status — these must be unchanged after all operations.

### 2. Run attach (human form)

```
node bin/aof.mjs boards milestone attach coordination --milestone v1.8 --roadmap .planning/ROADMAP.md
```

Capture the human-readable output.

**Expected human output:**
```
Attached board coordination to milestone v1.8
roadmap: .planning/ROADMAP.md
binding: attached
sync: aof boards sync coordination --milestone v1.8
```

If the command exits non-zero or shows an SDK error, stop and log as a BLOCKER finding. Do not proceed to sync until attach succeeds.

### 4. Verify post-attach state

Run `git diff .aof/boards/coordination/BOARD.json` and confirm:
- `gsd.milestone.status` changed from `"synced"` → `"ready_to_sync"`
- `gsd.milestone.syncedAt` changed from timestamp → `null`
- `gsd.milestone.binding.status` changed from `"synced"` → `"attached"`
- `gsd.milestone.id` still `"v1.8"` (unchanged)

Run `git diff .aof/boards/coordination/executions/` and confirm:

- `phase-40.json` is **unchanged**
