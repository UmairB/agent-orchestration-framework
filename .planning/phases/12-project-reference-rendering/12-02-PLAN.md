# Phase 12 Wave 2 Plan: Apply And Sync Global Reference Rendering

## Objective

Wire resolved global references into `aof apply` and `aof sync` so referenced global skills, agents, and rules render alongside project-local resources without copying source assets into project `.aof`.

## Planning Assumptions

- Wave 1 adds `globalRefs` validation and a reusable way to resolve referenced global resources.
- Global asset bodies and runtime overrides remain owned by the global workspace.
- Project-local overrides of referenced global assets are deferred.
- Associated helper/code file copying remains Phase 13.

## Requirements Covered

- **GREF-01:** User can reference global assets without copying them into project `.aof`.
- **GRND-01:** `aof apply` renders referenced global assets into Claude Code and Codex outputs.
- **GRND-02:** `aof sync` includes referenced global assets in validation, warnings, and render planning.
- **GRND-04:** Runtime overrides on global assets are honored during rendering.

## Decisions Covered

- **D-05:** The global asset remains the source of truth.
- **D-06:** Runtime overrides declared on the global asset are honored.
- **D-07:** Project-local global-asset overrides are deferred.
- **D-12:** Referenced global resources render alongside local resources.
- **D-13:** Resolved resources preserve source scope internally.

## Tasks

1. Add a shared project-load path for references.
   - Introduce or finalize a helper such as `loadProjectConfig(configPath, options)` that resolves local resources plus referenced global resources.
   - Include the original project `globalRefs` in the returned normalized config for diagnostics and inspection.
   - Preserve `packages`, `mcpServers`, `hooks`, `projectDocs`, and `settings` behavior from current `loadConfig()`.
   - Ensure referenced global resources resolve file-backed bodies and runtime overrides from `~/.aof`, not the project `.aof`.

2. Update `aof apply`.
   - Replace the direct `loadConfig(configPath)` call in `applyCommand()` with the project-aware resolver.
   - Ensure adapter warnings include referenced global resources.
   - Ensure `createRenderPlan()` sees both local and referenced global resources.
   - Preserve `--global` runtime-output semantics; this phase is about source references, not output scope.

3. Update `aof sync`.
   - Use the same project-aware resolver in `src/sync.mjs`.
   - Ensure sync dry-run shows create/update/delete/drift actions for referenced global resources.
   - Ensure framework package behavior is unchanged and still comes from project config packages.
   - Ensure `sync --strict` continues to fail on adapter warnings before writes.

4. Preserve no-copy behavior.
   - Add or extend BDD steps to create project configs with `globalRefs`.
   - Assert referenced global assets render into `.claude/` and `.codex/`.
   - Assert project `.aof/assets/...` does not receive copied global source files.
   - Include at least one global runtime override scenario and assert the rendered output uses the override.

5. Add focused unit/integration coverage.
   - Cover apply rendering of referenced global skills and rules.
   - Cover sync dry-run/real write path for referenced global assets.
   - Cover adapter warning collection when a referenced global asset has warning-producing metadata.

6. Verify wave 2.
   - Run `npm run test:unit`.
   - Run `npm test`.

## Acceptance Criteria

- `aof apply` renders referenced global assets to selected runtimes.
- `aof sync` plans and writes referenced global asset outputs through the same render path.
- Global runtime overrides are honored.
- Project `.aof/assets` is not populated with copied global source files.
- Existing local resource and package rendering behavior is unchanged.
