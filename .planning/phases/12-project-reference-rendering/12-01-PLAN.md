# Phase 12 Wave 1 Plan: Global Reference Model And Validation

## Objective

Add the project config model for `globalRefs` and validate referenced global assets without scanning unrelated global library drafts.

## Planning Assumptions

- Phase 11 provides `globalWorkspacePaths()`, `AOF_GLOBAL_HOME`, and whole-library `aof global validate`.
- Project references use top-level `globalRefs` entries shaped as `{ kind, id }`.
- Global references are limited to `skill`, `agent`, and `rule` in Phase 12.
- Rendering and lock integration are handled in later waves.

## Requirements Covered

- **GREF-01:** User can reference global assets by ID from a project `.aof` config without copying the asset into the project.
- **GREF-02:** User receives clear validation errors when a project references a missing global asset.
- **GREF-03:** AOF detects local/global asset ID conflicts and requires an explicit resolution.

## Decisions Covered

- **D-01:** Use top-level `globalRefs`.
- **D-02:** Global reference entries are object-shaped `{ kind, id }`.
- **D-03:** Do not copy global resource objects into project `resources`.
- **D-04:** Do not overload `resources[].source`.
- **D-08:** Missing referenced global assets are validation errors.
- **D-09:** Local/global `kind:id` conflicts are validation errors.
- **D-10:** Duplicate `globalRefs` are validation errors.
- **D-11:** Unreferenced malformed global assets do not fail project validation.

## Tasks

1. Add schema support for `globalRefs`.
   - Extend `schemas/aof.schema.json` with a top-level `globalRefs` array.
   - Define items with required `kind` and `id`.
   - Restrict `kind` to `skill`, `agent`, and `rule`.
   - Allow future extension fields only if consistent with existing schema permissiveness.

2. Add raw config validation for `globalRefs`.
   - Extend `src/config-inspect.mjs` to validate that `globalRefs` is an array when present.
   - Validate each reference object, required `kind`, required `id`, and allowed kind.
   - Detect duplicate `globalRefs` by normalized `kind:id`.
   - Detect local `resources` and `globalRefs` conflicts by normalized `kind:id`.

3. Add referenced global lookup validation.
   - Load the global manifest only when project config contains at least one valid-looking reference.
   - Report clear diagnostics when the global manifest is missing but references exist.
   - Report clear diagnostics when a referenced `kind:id` is not registered globally.
   - Validate only referenced global resource entries and file-backed bodies/overrides.
   - Preserve Phase 11 behavior: malformed unreferenced global assets do not fail project validation.

4. Add resolver scaffolding without changing render call sites yet.
   - Add a shared helper in `src/dsl.mjs` or a focused new module that can resolve referenced global resources with the global config directory as base.
   - Keep existing `loadConfig(configPath)` behavior stable for callers that do not need global references.
   - Ensure resolved global resources can carry source metadata for later waves.

5. Add unit tests.
   - Cover schema acceptance for valid `globalRefs`.
   - Cover invalid global reference shape diagnostics.
   - Cover duplicate reference diagnostics.
   - Cover missing global asset diagnostics.
   - Cover local/global conflict diagnostics.
   - Cover malformed unreferenced global assets being ignored by project validation.

6. Verify wave 1.
   - Run `npm run test:unit`.

## Acceptance Criteria

- Project configs can declare `globalRefs` without schema or validation rejection.
- Missing referenced global assets produce actionable project validation errors.
- Duplicate references and local/global `kind:id` conflicts fail validation.
- Project validation only checks referenced global assets.
- Existing project-local validation remains unchanged when `globalRefs` is absent.
