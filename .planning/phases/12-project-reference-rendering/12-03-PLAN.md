# Phase 12 Wave 3 Plan: Global Reference Diagnostics And Lock Traceability

## Objective

Complete Phase 12 by exposing source scope in diagnostics and lock state, hardening conflict output, documenting project references, and verifying the phase end to end.

## Planning Assumptions

- Wave 2 renders referenced global resources through apply and sync.
- Resolved global resources carry source metadata into render planning.
- Lock metadata should remain compatible with existing lock consumers while adding explicit global scope.

## Requirements Covered

- **GREF-04:** Project diagnostics show whether each rendered asset came from project-local source or the global library.
- **GRND-01:** Re-verify apply rendering with user-facing BDD coverage.
- **GRND-02:** Re-verify sync planning and writes with global references.
- **GRND-03:** Lock state records global asset source scope for generated outputs.

## Decisions Covered

- **D-13:** Resolved resources preserve source scope.
- **D-14:** Lock entries for referenced global assets record `scope: "global"` and source identity.
- **D-15:** Human and JSON diagnostics expose referenced global assets separately where practical.

## Tasks

1. Add lock source metadata.
   - Update `src/adapters.mjs` resource metadata so global resources include stable source scope.
   - Prefer lock entries shaped with `resource.scope = "global"` plus `kind`, `id`, and global origin details.
   - Preserve package metadata behavior.
   - Preserve local resource lock entries or add `scope: "local"` only if it does not break existing assertions.

2. Improve render-plan conflict descriptions.
   - Update `src/render-plan.mjs` output descriptions so conflicts identify `global:<kind>:<id>` distinctly from local and package resources.
   - Ensure local/global output conflicts produce actionable error messages.
   - Keep Codex rule safe merge behavior intact when all merged rule outputs are compatible.

3. Expose reference diagnostics and inspection.
   - Extend `inspectConfig()` output with `globalRefs` and/or source-scoped resources.
   - Update human `config show` output to label global references without noisy detail.
   - Ensure JSON output includes enough information for UI/API work in Phase 14.
   - Update `doctorConfig()` checks or suggestions if missing/conflicting global references are present.

4. Add BDD coverage for diagnostics and lock state.
   - Assert `aof config show` or `doctor` identifies referenced global assets.
   - Assert `.aof/aof.lock.json` contains a global source marker for generated referenced assets.
   - Assert missing global references fail with clear text.
   - Assert local/global `kind:id` conflicts fail with clear text.
   - Assert sync and apply continue to pass for valid references.

5. Update README and help-adjacent docs.
   - Document `globalRefs` project config syntax.
   - Show a minimal flow: `aof global add`, project `globalRefs`, `aof apply`.
   - State that references do not copy source files into project `.aof`.
   - State that associated helper files are handled in a later phase.

6. Run full Phase 12 verification.
   - Run `npm run test:unit`.
   - Run `npm test`.
   - `npm run ui:build` is not required unless UI files are changed unexpectedly.

7. Update Phase 12 completion state.
   - Write `.planning/phases/12-project-reference-rendering/12-03-SUMMARY.md`.
   - Write `.planning/phases/12-project-reference-rendering/12-VERIFICATION.md`.
   - Update roadmap, requirements traceability, project state, and project summary after execution.

## Acceptance Criteria

- Lock entries identify referenced global assets as global source outputs.
- Config inspection and diagnostics expose global references/source scope.
- Missing references and local/global conflicts are actionable in CLI output.
- README documents `globalRefs` and no-copy behavior.
- Unit and BDD verification pass.
