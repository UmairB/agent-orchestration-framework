# 37-02 Plan: Assignment Execution Records

## Goal

Route phase-task assignment through the SDK phase runner and persist typed execution results without breaking existing board/task UI consumers.

## Tasks

1. Update `src/board-execution.mjs`.
   - Add injectable `phaseRunner` option for tests; default to adapter `runGsdPhase`.
   - On assignment, create an execution record that includes existing command/handoff fields and an additive `sdkResult`.
   - Map successful SDK results to `complete` execution status and `done` board task status.
   - Map failed SDK/adapter results to `failed` execution status and `blocked` board task status with `errorSubtype`, `errorMessages`, and log entries.

2. Preserve user-facing compatibility.
   - Keep command strings in `execution.commands` and `resume.commands`.
   - Keep `task.execution.provider/status/phase/executionPath/updatedAt`.
   - Update CLI output to report the actual resulting execution status.

3. Update tests and BDD.
   - Unit-test assignment success through fake SDK result.
   - Unit-test failed `error_max_turns` or `error_during_execution` result.
   - Adjust board BDD assignment expectations from `running` to the new deterministic SDK-result status where fixture injection is used.
