# 38-03 Plan: Board JSON Parity And Milestone Closeout

## Goal

Finish the v1.7 surface by making typed board failures consistently machine-readable, documenting the doctor command, and producing closeout-ready verification evidence.

## Tasks

1. Sweep board command JSON errors.
   - Audit `boards sync`, `boards milestone attach/status/answer`, `boards repair`, `boards task assign`, `boards execution show/update`, and `boards doctor`.
   - For typed errors under `--json`, print `{ ok: false, code, message, expected?, actual?, next? }` and set `process.exitCode = 1`.
   - Keep successful JSON payloads backward compatible where already shipped.
   - Avoid rewriting unrelated asset/package/project command handling.

2. Ensure remediation hints.
   - Review `BoardLifecycleError` and `GsdSdkError` paths reachable from board commands.
   - Add or tighten `next` hints for missing milestone, mismatch, missing tools, incomplete milestone, unsupported backend, missing task execution, and failed phase execution.
   - Preserve human output quality for non-JSON users.

3. Update docs and help.
   - Add `aof boards doctor [<board-id>] [--json]` to help text and README board section.
   - Document the v1.6 migration hint and the SDK/tool version drift warning.

4. Add BDD parity.
   - Add Node BDD scenarios for JSON structured errors on representative board commands.
   - Mirror the relevant scenarios in the PowerShell runner.
   - Keep fixture env use deterministic; do not invoke real GSD phase execution.

5. Final verification and phase artifacts.
   - Run the full Phase 38 verification set.
   - Write 38-01/02/03 summaries and 38-VERIFICATION.md.
   - Update ROADMAP/REQUIREMENTS/STATE for completed Phase 38.
   - Leave milestone audit/archive to the autonomous lifecycle step after Phase 38 verification passes.
