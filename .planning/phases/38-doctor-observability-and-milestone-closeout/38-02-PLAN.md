# 38-02 Plan: SDK Toolchain Observability And Windows Checks

## Goal

Expose and persist SDK/toolchain metadata so doctor can report version drift, missing tools, and Windows-specific environmental risks.

## Tasks

1. Add adapter metadata probing.
   - Add an exported adapter function such as `inspectGsdToolchain(projectDir, options = {})`.
   - Report bundled SDK version, resolved `gsd-tools.cjs` path, and best-effort tools version.
   - Keep `@gsd-build/sdk` imports inside `src/gsd-sdk-adapter.mjs`.
   - Normalize unavailable tools into stable diagnostics rather than raw process errors.

2. Record lock metadata.
   - Add a lock helper that shallow-merges a `gsd` metadata object into existing lock state.
   - Preserve `files`, `packages`, `frameworks`, and `frameworkInstallAttempts`.
   - Update adapter boot paths that resolve tools to write metadata when safe.
   - Unit-test missing lock, existing lock preservation, and metadata replacement.

3. Add drift and missing-tools checks to doctor.
   - Emit `SDK_VERSION_DRIFT` as `warn` when bundled SDK version and tools version are both known and differ.
   - Emit `GSD_TOOLS_MISSING` as `fail` when tools cannot be resolved/executed.
   - Include `expected`, `actual`, or `next` details where useful in JSON.

4. Add Windows-oriented checks.
   - Add `NODE_ON_PATH` pass/fail check using a small process probe.
   - Add `WINDOWS_UNC_PATH` warning when the project dir is a UNC path.
   - Strip UTF-8 BOM in adapter JSON parsing and add a doctor warning when `.planning/STATE.md` or `.planning/ROADMAP.md` starts with BOM.
   - Keep these checks stable on non-Windows by reporting pass/skip-like neutral results rather than noisy warnings.

5. Add coverage.
   - Unit-test metadata probe with injected tools/path outcomes.
   - Unit-test lock metadata preservation.
   - BDD-test doctor drift/missing-tools payloads through fixtures.
   - Ensure PowerShell integration covers the Windows path-space case and at least one Windows-specific doctor check.

## Verification

- `node scripts/check-sdk-boundary.mjs`
- `npm run test:unit`
- `npm test`
- `npm run test:integration:ps`

## Acceptance Criteria

- `aof boards doctor --json` can report SDK/tool versions and drift.
- Missing tools show `GSD_TOOLS_MISSING` with a remediation hint.
- `.aof/aof.lock.json` records SDK/tool metadata without dropping existing lock state.
- BOM/UNC/node checks are visible in doctor output and do not break non-Windows runs.
