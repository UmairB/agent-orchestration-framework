# 38-01 Plan: Board Doctor And Migration Diagnostics

## Goal

Add the board/GSD health ladder and v1.6 migration diagnostic that answer whether a board is ready to sync and execute.

## Tasks

1. Add board doctor data model.
   - Create `doctorBoards(projectDir, options = {})` in `src/boards.mjs` or a nearby board diagnostics module.
   - Return `{ ok, checks }` where each check has `{ status: "pass"|"warn"|"fail", code, message, boardId?, next? }`.
   - Support optional board id filtering.
   - Keep the function read-only.

2. Implement core health checks.
   - Board state exists and validates.
   - GSD-backed boards report milestone binding state.
   - Missing milestone id on v1.6-shaped boards emits `BOARD_MILESTONE_ID_MISSING`.
   - Bound milestone id is checked through the existing backend/adapter assertion path.
   - Roadmap analysis can load and has phases.
   - Synced board tasks match cached roadmap phase ids; stale/missing tasks produce warnings or failures with exact sync/repair hints.

3. Implement v1.6 migration hinting.
   - Reuse the same inference criteria as `repairMissingMilestoneId()` without writing.
   - If one safe milestone candidate exists, include it in `next`.
   - If inference is unsafe, emit `<milestone-id>` in `next`.
   - Never mutate board state from doctor.

4. Wire CLI and help.
   - Add `aof boards doctor [<board-id>] [--json]`.
   - Human output prints a compact ladder and `next:` hints.
   - JSON output prints `{ ok, checks }`.
   - Add command to help text.

5. Add coverage.
   - Unit-test healthy board, missing milestone id, unsafe inference, and task/phase mismatch.
   - Add Node BDD for `boards doctor` human and JSON output.
   - Mirror BDD behavior in the PowerShell runner.

## Verification

- `npm run test:unit`
- `npm test`
- `npm run test:integration:ps`

## Acceptance Criteria

- `aof boards doctor` shows a pass/warn/fail ladder for all boards.
- `aof boards doctor delivery --json` returns stable check objects.
- v1.6-shaped boards emit `BOARD_MILESTONE_ID_MISSING` with an exact attach command when inferable.
- Doctor performs no writes.
