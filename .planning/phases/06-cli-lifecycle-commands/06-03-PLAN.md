# Phase 6 Wave 3 Plan: Sync And Clean Lifecycle Commands

## Goal

Add `aof sync` and `aof clean` as safe lifecycle commands that reconcile `.aof/` intent, preserve network and drift boundaries, and manage lock-owned generated outputs without deleting user-owned files.

## Requirements Covered

- **CLI-06:** User can run one command that reconciles declared packages and generated runtime outputs.
- **CLI-09:** User can remove generated outputs owned by AOF without deleting source `.aof/` files.

## Decisions Covered

- **D-01:** Phase 6 primary commands include `aof sync` and `aof clean`.
- **D-02:** Keep `aof apply` as the existing write command.
- **D-05:** `sync` reconciles package intent plus generated runtime outputs.
- **D-06:** `sync` does not run networked installers by default.
- **D-07:** `sync --dry-run` shows the full package/output/lock/install plan and writes nothing.
- **D-08:** `sync` preserves drift and continues safe actions like current `apply`.
- **D-13:** `clean` deletes lock-owned outputs only.
- **D-14:** `clean` preserves drifted files by default.
- **D-15:** `clean` updates lock file entries after deletion while preserving package intent and install attempts.
- **D-16:** `clean --dry-run` previews all clean actions and lock changes without writing.

## Implementation Tasks

1. Add reusable sync planning.
   - Create `src/sync.mjs` or equivalent to keep `src/cli.mjs` thin.
   - Resolve config through `findProjectConfig()` and `loadConfig()`.
   - Build generated output actions using `createRenderPlan()` and `planApplyActions()`.
   - Build framework/package installer plans using existing `planFrameworkInstall()` for declared packages where supported.
   - Produce a combined plan object that can print human-readable output and JSON if `--json` is cheap to support.

2. Implement `aof sync` execution.
   - Route `aof sync`.
   - Support runtime filters, `--global`, `--force`, `--dry-run`, and explicit installer execution via `--install`.
   - In normal mode without `--install`, execute safe generated-output actions and write lock state, but only print installer commands/next steps.
   - With `--install`, reuse existing network-boundary output and framework execution behavior.
   - Preserve `apply` behavior; do not rename or remove `aof apply`.

3. Implement full dry-run output for sync.
   - Print generated-output actions.
   - Print lock preview.
   - Print package/install commands and clearly state whether network execution is disabled.
   - Write no files, no lock, and run no installers.

4. Add clean planning and execution.
   - Create `src/clean.mjs` or equivalent.
   - Read `.aof/aof.lock.json`; if missing or no file entries exist, print a clear no-op result.
   - For each lock file entry, hash the current file.
   - Plan `delete` for matching lock-owned files.
   - Plan `skip` for absent files.
   - Plan `drift-warning` for files whose current hash differs from the lock hash.
   - Execute deletes only for matching lock-owned files.
   - Rewrite lock state with deleted file entries removed and drifted/skipped ownership preserved as appropriate.
   - Preserve `frameworks` and `frameworkInstallAttempts` in the lock.

5. Add clean dry-run.
   - Route `aof clean --dry-run`.
   - Print delete, skip, drift-warning, and lock-change preview.
   - Write nothing and delete nothing.

6. Add tests.
   - BDD: `aof sync --dry-run` on package config prints generated output plan, lock preview, and installer command while writing nothing.
   - BDD: `aof sync` applies generated outputs and writes lock without running installer commands by default.
   - BDD: `aof sync --install` uses existing simulated framework status support and records attempts.
   - BDD: `aof sync` preserves drift like `apply`.
   - BDD: `aof clean --dry-run` previews deletes and lock changes.
   - BDD: `aof clean` deletes matching lock-owned outputs and removes only those file entries from lock.
   - BDD or unit: drifted lock-owned file is preserved and remains in lock.
   - Unit: clean planner handles missing lock, absent files, matching files, drifted files, and package intent preservation.

## Acceptance Criteria

- `aof sync` reconciles package intent plus generated runtime outputs.
- `aof sync` does not run networked installers by default.
- `aof sync --dry-run` writes nothing and prints the full plan.
- Drift behavior in `sync` matches current `apply` safety.
- `aof clean` deletes only lock-owned matching generated files.
- `aof clean` preserves drifted files and source `.aof/` files.
- `aof clean` updates lock file entries without losing framework intent or install attempts.
- `aof clean --dry-run` writes nothing and previews planned actions.
