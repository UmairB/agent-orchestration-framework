# Plan 34-03: CLI, Setup API, And Compact UI Status

## Goal

Surface the typed lifecycle through existing CLI and setup UI paths without adding new routes or richer UI affordances.

## Tasks

1. Update `src/cli.mjs` board sync, show, create, repair, and milestone attach output to include compact binding status where relevant.
2. Make `boards sync` allow missing `--milestone` to reach the board layer so the typed `MILESTONE_MISSING_ARG` code and `next` hint are preserved, especially for `--json`.
3. Add CLI JSON error serialization for changed board commands so typed board errors return `{ok:false, code, message, expected?, actual?, next?}`.
4. Update `src/setup-ui.mjs` error responses to preserve typed error `code`, `expected`, `actual`, and `next` fields when board errors are thrown.
5. Update `ui/src/main.tsx` board types and compact board detail/status display to show `milestone: <status> - binding: <status>`.
6. Keep existing setup API route shapes: `/api/boards`, `/api/boards/:id`, `/api/boards/:id/sync`, and `/api/boards/:id/repair`.

## Decision Coverage

- D-01: CLI and JSON output preserve missing milestone code and next hint.
- D-15: UI shows milestone status next to binding status.
- D-16: UI displays drift/error as short binding labels only.
- D-17: Existing board APIs return additive binding fields with no new routes.
- D-18: UI treatment stays compact text only.

## Acceptance Criteria

- LIFE-04 and the Phase 34 UI decisions are covered.
- D-01, D-15, D-16, D-17, and D-18 are covered by the CLI/API/UI output work in this plan.
- No new setup UI routes, panels, badges, or interactions are introduced.
- CLI and setup API still preserve existing non-GSD board behavior.
