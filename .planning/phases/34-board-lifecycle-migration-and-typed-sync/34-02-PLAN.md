# Plan 34-02: Lifecycle Attach, Repair, And v1.6 Migration

## Goal

Move create, attach, repair, validation, and manual task gates onto the new binding lifecycle without breaking existing v1.6 board files.

## Tasks

1. Update GSD-backed board creation to write `gsd.milestone.binding.status = "pending-attachment"` while preserving legacy `gsd.milestone.status = "waiting_for_user"` for display.
2. Update `attachBoardMilestoneRoadmap` to verify the requested milestone with `assertMilestone()` before writing any board state.
3. On successful attach, write `binding.status = "attached"`, `binding.sdkVersion`, milestone id, normalized sync command, and compatibility milestone status fields.
4. Update `repairBoard` to:
   - detect v1.6 boards with roadmap path but missing milestone id;
   - analyze SDK roadmap state;
   - auto-bind only exactly one safe candidate;
   - emit a manual attach command without writing for ambiguous cases;
   - normalize `gsd.taskCreation.syncCommand` to include `--milestone` once bound.
5. Update `validateBoardShape` to warn with `BOARD_MILESTONE_ID_MISSING` and an exact migration command when a v1.6-shaped board lacks `gsd.milestone.id`.
6. Update manual task creation blocking to require `gsd.milestone.binding.status === "synced"` for GSD-backed boards, with v1.6-compatible fallback only where needed for existing data.

## Decision Coverage

- D-06: Lifecycle gates use `gsd.milestone.binding.status` while preserving legacy status for display.
- D-07: Lifecycle writes only the supported binding status set.
- D-09: Attach/repair/sync failures do not pretend a partial state is synced.
- D-10: Lifecycle writes `binding.sdkVersion`.
- D-11: Repair auto-binds v1.6 boards only for exactly one safe SDK milestone candidate.
- D-12: Ambiguous repair emits a manual attach command and makes no binding guess.
- D-13: Validation warns for missing `gsd.milestone.id` during migration.
- D-14: Repair normalizes legacy sync commands after binding.

## Acceptance Criteria

- LIFE-01, LIFE-02, LIFE-03, LIFE-04, LIFE-05, MIG-02, and MIG-04 are covered.
- D-06, D-07, D-09, D-10, D-11, D-12, D-13, and D-14 are covered by the lifecycle, repair, and migration work in this plan.
- Unknown milestone attach attempts fail without modifying BOARD.json.
- Ambiguous repair makes no binding guess and returns an actionable command.
