# Phase 23 Wave 1 Plan: Shared Capability And Validation Contract

## Objective

Make the central AOF capability model and validation layer reflect the real runtime contract: Claude supports command assets, Codex does not, and simple assets cannot declare or imply argument handling.

## Planning Assumptions

- Existing resources are simple assets unless a later phase introduces workflow-backed mode.
- Codex command rejection is a hard validation error, not an adapter warning.
- The setup UI already consumes central capability status through `capabilitiesPayload()` and `capabilityDiagnostics()`.
- This plan does not add workflow assets, skill/workflow reference placeholders, or argument metadata fields for workflow-backed assets.

## Requirements Covered

- **RTS-01:** Claude command support remains native.
- **RTS-02:** Codex command targeting is invalid.
- **RTS-03:** Validation diagnostics explain unsupported runtime/resource combinations.
- **RTS-04:** Codex skill assets remain valid and explicit.
- **SIMPLE-01:** Simple assets remain the default direct-render model.
- **SIMPLE-02:** Simple assets reject argument configuration.
- **SIMPLE-03:** Simple asset content with argument markers gets validation guidance.

## Decisions Covered

- **D-01..D-05:** Central support matrix and no command-to-Codex-skill mapping.
- **D-06:** Config validation fails for direct and implicit Codex command targeting.
- **D-11..D-15:** Simple assets stay workflow-free and cannot support arguments.
- **D-16..D-18:** Shared model, diagnostics, and existing setup UI capability payloads are updated without broader UI workflow authoring.

## Tasks

1. Update the central capability matrix.
   - Change `CAPABILITIES.command.codex` in `src/model.mjs` from `native` to `unsupportedFail`.
   - Keep `CAPABILITIES.command.claude` as `native`.
   - Preserve existing `rule.codex` mapped behavior and other capability statuses.

2. Add reusable resource capability validation in `src/config-inspect.mjs`.
   - After normal resource kind/id/runtime validation, evaluate each effective runtime for the resource kind.
   - Treat omitted `resource.runtimes` as `supportedRuntimes()` for validation purposes.
   - Emit an error for any `CAPABILITY_STATUS.unsupportedFail` runtime/resource pair.
   - Use a stable diagnostic code such as `unsupported-runtime-capability`.
   - For `kind: "command"` and runtime `codex`, the message must say command assets are not supported for Codex and users should target Claude commands or create a Codex skill explicitly.

3. Keep setup UI validation aligned.
   - Confirm `src/config-editor.mjs` already turns `unsupportedFail` capability diagnostics into blocking errors.
   - If needed, adjust wording in `capabilityDiagnostic()` so `command is not supported for codex` is clear enough for the setup UI save response.
   - Do not redesign UI mode controls in this plan.

4. Add simple argument validation.
   - Reject explicit argument configuration fields if present on simple resources, such as `arguments`, `args`, `argumentHint`, `argument-hint`, or equivalent existing input shapes.
   - Detect obvious argument markers in resource body content: `$ARGUMENTS`, `{{GSD_ARGS}}`, `argument-hint`, and `{{args...}}`.
   - Inspect file-backed body content through the existing validation path where files are already read.
   - Inspect inline runtime override bodies when available.
   - Inspect external runtime override bodies where they are already read for override validation.
   - Emit a diagnostic code such as `simple-asset-arguments` with guidance that arguments belong to workflow-backed assets.

5. Add focused unit coverage.
   - Update `test/model.test.mjs` to assert `CAPABILITIES.command.codex === CAPABILITY_STATUS.unsupportedFail`.
   - Add `test/config-inspect.test.mjs` coverage for:
     - command with `runtimes: ["codex"]` fails validation.
     - command with omitted `runtimes` fails because Codex is implicit.
     - command with `runtimes: ["claude"]` passes this capability check.
     - skill with `runtimes: ["codex"]` remains valid.
     - simple content containing `$ARGUMENTS` or `{{GSD_ARGS}}` fails with argument guidance.
     - runtime override body containing `{{args.phase}}` fails with argument guidance.
   - Add or update `test/config-editor.test.mjs` coverage proving the setup UI save validation blocks a Codex command target.

## Acceptance Criteria

- `aof project validate` reports a hard error for command assets that target Codex directly or implicitly.
- A command resource must specify `runtimes: ["claude"]` to be valid.
- A Codex skill resource remains valid.
- Simple asset content and overrides that contain obvious argument markers produce a validation diagnostic.
- Setup UI validation returns a blocking diagnostic for Codex command resources through the existing capabilities path.

## Verification

- `npm run test:unit`
- Focused checks:
  - `node ./test/unit.mjs` if available locally.
  - `node bin/aof.mjs project validate --target <fixture>` against Codex command and Claude command fixtures.
