# Phase 28 Wave 3 Plan: CLI And Setup UI API Foundation With BDD Coverage

<objective>
Expose board/task operations through `aof boards ...`, setup UI API routes, and required Node plus PowerShell BDD coverage.
</objective>

<context>
Read before execution:
- `.planning/phases/28-board-and-task-state-foundation/28-CONTEXT.md`
- `.planning/phases/28-board-and-task-state-foundation/28-RESEARCH.md`
- `src/cli.mjs`
- `src/setup-ui.mjs`
- `test/integration/cli.mjs`
- existing BDD step modules
</context>

<tasks>

1. **Add the `aof boards` CLI namespace.**
   - Type: code
   - Files: `src/cli.mjs`
   - Action:
     - Route `aof boards ...` at top level.
     - Implement `list`, `create`, `show`, `archive`, `validate`, `index`, `task add`, and `task move`.
     - Support `--json`, `--target`, and `--strict` where appropriate.
     - Update help text with the board namespace.
   - Acceptance criteria:
     - Board/task operations are scriptable through the CLI.
     - Validation exits non-zero for errors and for strict warnings.

2. **Add setup UI API routes.**
   - Type: code
   - Files: `src/setup-ui.mjs`
   - Action:
     - Add backend API routes for listing boards, showing a board, creating/archiving boards, adding tasks, moving tasks, rebuilding the index, and validating state.
     - Reuse `src/boards.mjs`; do not add Phase 31 visual UI yet.
   - Acceptance criteria:
     - Setup UI can consume board/task data in a later phase.
     - API diagnostics use the existing JSON error pattern.

3. **Add BDD coverage.**
   - Type: test
   - Files: `test/integration/features/boards.feature`, `test/integration/cli.mjs`, `test/integration/steps/boards.steps.mjs`, `test/integration-ps/steps/boards.steps.ps1`
   - Action:
     - Cover board creation/list/show, task add/move/history, index rebuild, stale index warning, and validation failure for malformed canonical state.
     - Add PowerShell parity for the same board feature scenarios.
   - Acceptance criteria:
     - `npm test` and `npm run test:integration:ps` exercise board behavior through BDD.

4. **Add setup UI API tests.**
   - Type: test
   - Files: `test/setup-ui.test.mjs`
   - Action:
     - Cover board list/create/show, task add/move, index rebuild, and validation endpoint behavior over real HTTP.
   - Acceptance criteria:
     - `npm run test:unit` covers the setup API foundation.

</tasks>

<verification>
- `npm run test:unit`
- `npm test`
- `npm run test:integration:ps`
</verification>

<success_criteria>
- All Phase 28 requirements are reachable through supported CLI/API surfaces.
- BDD coverage exists for the new board/task lifecycle.
- The setup UI has backend APIs ready for Phase 31 without pulling visual UI work into Phase 28.
</success_criteria>
