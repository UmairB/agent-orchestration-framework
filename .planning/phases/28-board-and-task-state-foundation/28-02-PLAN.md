# Phase 28 Wave 2 Plan: Task Index/cache Generation And Validation

<objective>
Add a rebuildable `.aof/cache/boards/index.json` and validation diagnostics for malformed canonical board/task state.
</objective>

<context>
Read before execution:
- `.planning/phases/28-board-and-task-state-foundation/28-CONTEXT.md`
- `.planning/phases/28-board-and-task-state-foundation/28-RESEARCH.md`
- `src/boards.mjs`
- `src/config-inspect.mjs` for diagnostic style
</context>

<tasks>

1. **Generate a board index from canonical files.**
   - Type: code
   - Files: `src/boards.mjs`
   - Action:
     - Add `buildBoardIndex()` and `writeBoardIndex()`.
     - Include board summaries, task summaries, status counts, generated timestamp, and a canonical fingerprint.
     - Write index to `.aof/cache/boards/index.json`.
   - Acceptance criteria:
     - The index is fully rebuildable from `.aof/boards`.
     - UI/API callers can read summarized board/task state without scanning all task files.

2. **Validate board and task files.**
   - Type: code
   - Files: `src/boards.mjs`
   - Action:
     - Add `validateBoards()`.
     - Emit stable diagnostics for malformed board JSON, malformed task JSON, duplicate IDs, missing board references, invalid statuses, malformed refs, and stale/missing index state.
     - Treat stale or missing index as a warning in Phase 28.
   - Acceptance criteria:
     - Canonical file errors block validation.
     - Cache freshness issues are visible but warning-only unless `--strict` is used by callers.

3. **Prefer cache reads when correct.**
   - Type: code
   - Files: `src/boards.mjs`
   - Action:
     - Add `readBoardIndex()` and `loadBoardIndexOrBuild()`.
     - Use the cache when its fingerprint matches canonical files; otherwise rebuild in memory and report stale state through validation.
   - Acceptance criteria:
     - File correctness remains authoritative.
     - Cache behavior prepares Phase 31 UI consumption.

4. **Add validation/index unit coverage.**
   - Type: test
   - Files: `test/boards.test.mjs`
   - Action:
     - Cover index rebuild, cache fingerprint, stale index warning, malformed board/task files, invalid status, and missing board references.
   - Acceptance criteria:
     - STATE-02 through STATE-04 are covered by focused tests.

</tasks>

<verification>
- `npm run test:unit`
</verification>

<success_criteria>
- STATE-02 is satisfied by a rebuildable generated index.
- STATE-03 is satisfied by board/task/cache diagnostics.
- STATE-04 is satisfied by cache-aware reads that preserve canonical correctness.
</success_criteria>
