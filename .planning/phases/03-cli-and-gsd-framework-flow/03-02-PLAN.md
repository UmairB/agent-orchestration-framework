# Phase 3 Wave 2 Plan: Config-Aware GSD Install, Attempt Recording, And Lock Replay

## Goal

Make `aof install gsd` resolve managed GSD package intent from `.aof/`, preview exact installer commands, execute one command per runtime with explicit network boundaries, record every attempt in lock state, and support explicit replay from lock.

## Requirements Covered

- **FRAM-01:** user can declare GSD as a managed framework package in AOF.
- **FRAM-02:** user can install or preview GSD setup for Claude Code.
- **FRAM-03:** user can install or preview GSD setup for Codex.
- **CLI-01:** automation-friendly install and replay commands.

## Decisions Covered

- **D-09:** `aof install gsd` uses declared `.aof` package intent by default.
- **D-10:** CLI flags can override package intent for one run.
- **D-11:** `aof install gsd --dry-run` is the preview path.
- **D-12:** dry-run prints exact `npx get-shit-done-cc@...` commands and states no network/install runs.
- **D-13:** one installer command per runtime.
- **D-14:** real installs record each command attempt in `.aof/aof.lock.json`.
- **D-15:** attempt records include command, runtime, scope, exit status, timestamp, and package source or version/range.
- **D-20:** any runtime install failure fails the command overall.
- **D-21:** partial installs still record successes and failures.
- **D-22:** failures print exact retry commands.
- **D-23:** add explicit lock replay such as `aof install --from-lock`.
- **D-24:** real networked installer runs print a clear boundary before execution.
- **D-25:** boundary includes command, package source, runtime, scope, and npm/network warning.
- **D-26:** skip successful prior installs by default.
- **D-27:** `--force` reruns successful prior installs.

## Implementation Tasks

1. Add framework install planning.
   - Extend `src/frameworks.mjs` with a pure command-plan helper.
   - Resolve GSD package source from `.aof/aof.config.json` when declared.
   - Preserve CLI runtime and scope flags as one-run overrides.
   - Keep default package behavior for `aof install gsd` when no config package exists.
   - Support `--json` dry-run output for automation.

2. Implement dry-run preview.
   - Print one exact `npx get-shit-done-cc@...` command per selected runtime.
   - State clearly that no network or installer command will run.
   - Ensure dry-run does not write `.aof/aof.lock.json`.

3. Implement real execution boundaries.
   - Before each real command, print the command, package source, target runtime, scope, and npm/network execution warning.
   - Keep existing synchronous process behavior.
   - Add an injectable executor or explicit test simulation hook so tests never invoke real `npx`.

4. Record install attempts in lock state.
   - Extend lock helpers to merge framework install attempt records without losing `files` or `frameworks`.
   - Record command, runtime, scope, status, numeric exit status, timestamp, package source/range, and whether the run was skipped.
   - Write attempts for both successes and failures.
   - Fail overall after all selected runtime attempts complete when any attempt fails.

5. Add skip and force policy.
   - Read previous successful attempt records from `.aof/aof.lock.json`.
   - Skip successful matching package/runtime/scope attempts by default.
   - Print skipped runtime information and retry guidance.
   - Rerun matching successful attempts when `--force` is present.

6. Add lock replay.
   - Implement `aof install --from-lock`.
   - Replay managed GSD intent from lock state explicitly.
   - Support `aof install --from-lock --dry-run`.
   - Do not infer replay from generated `.claude/` or `.codex/` folders.

7. Add tests.
   - Unit tests for command planning, config package resolution, CLI override behavior, skip/force policy, and lock attempt merging.
   - BDD scenarios for dry-run preview for Claude and Codex.
   - BDD scenarios for config-declared package source.
   - BDD scenarios for simulated success, partial failure, retry command output, and lock attempt recording.
   - BDD scenarios for `install --from-lock --dry-run`.

## Acceptance Criteria

- `.aof/aof.config.json` can declare managed GSD package intent and `aof install gsd` uses it.
- `aof install gsd --dry-run` prints exact commands for Claude Code and Codex and performs no writes or network execution.
- Real install mode prints an explicit npm/network boundary before each runtime command.
- A failure in any runtime install causes overall command failure after attempts are recorded.
- Partial successes and failures are represented in `.aof/aof.lock.json`.
- Successful prior installs are skipped by default and rerun with `--force`.
- `aof install --from-lock --dry-run` previews replay commands from lock state.
