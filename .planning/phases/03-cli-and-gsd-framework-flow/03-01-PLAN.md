# Phase 3 Wave 1 Plan: Config Inspection, Validation, And Doctor Commands

## Goal

Add script-friendly config inspection commands that expose `.aof/` state in human-readable and JSON forms, with validation and doctor diagnostics that future install and interactive flows can reuse.

## Requirements Covered

- **CLI-01:** automation-friendly commands for catalog/config inspection.

## Decisions Covered

- **D-01:** add dedicated automation-friendly config inspection commands.
- **D-02:** include `aof config show`, `aof config validate`, and `aof config doctor`.
- **D-03:** human-readable output is default.
- **D-04:** support `--json` where practical.
- **D-05:** validation includes schema plus semantic checks.
- **D-06:** validation covers JSON shape, resource kinds/runtimes, file-backed paths, override identity, package ids, and runtime support.
- **D-07:** doctor goes beyond validation into project health.
- **D-08:** doctor includes config validity, stale legacy root config, generated-output drift summary, missing files, package install intent, and suggested next commands.

## Implementation Tasks

1. Add reusable config diagnostics.
   - Create `src/config-inspect.mjs` or equivalent.
   - Resolve the authoritative config path using the same `.aof/aof.config.json` precedence as existing CLI paths.
   - Produce a normalized show payload with project name, resources, packages, config path, and detected legacy root config state.
   - Add non-throwing validation diagnostics so commands can report multiple issues in one run.
   - Keep `resolveConfig()` behavior intact for existing callers.

2. Implement semantic validation.
   - Validate JSON root shape and array fields.
   - Validate supported resource kinds and runtimes from the central model.
   - Validate file-backed resource paths and override paths relative to the config file.
   - Validate override runtime keys and override identity consistency when an override declares an id.
   - Validate package ids, supported managed package shape, package runtimes, and GSD runtime support.

3. Implement doctor diagnostics.
   - Reuse Phase 2 render planning and lock comparison to summarize generated-output drift.
   - Report stale root `aof.config.json` when `.aof/aof.config.json` exists.
   - Report missing asset files, package install intent, and clear suggested next commands.
   - Keep doctor read-only.

4. Add CLI command routing and output.
   - Add `aof config show`.
   - Add `aof config validate`.
   - Add `aof config doctor`.
   - Add `--json` option parsing.
   - Print stable human-readable summaries by default.
   - Print structured JSON for `show`, `validate`, and `doctor`.
   - Return non-zero for validation failure and doctor failure only when diagnostics are errors, not warnings.

5. Update help text and docs.
   - Add `config` commands to CLI help.
   - Document automation-friendly inspection examples in `README.md`.

6. Add tests.
   - Unit tests for diagnostic helpers.
   - BDD scenarios for human and JSON `config show`.
   - BDD scenarios for valid and invalid `config validate`.
   - BDD scenarios for `config doctor` drift/missing-file/package-intent output.

## Acceptance Criteria

- `aof config show` prints the authoritative `.aof/` config summary.
- `aof config show --json` emits valid JSON with config path, resources, packages, and diagnostics metadata.
- `aof config validate` reports schema and semantic validation results.
- `aof config validate --json` emits machine-readable diagnostics and exits non-zero on errors.
- `aof config doctor` is read-only and reports project health, generated drift summary, stale legacy config, package intent, and suggested next commands.
- Existing `init`, `apply`, `install`, and `catalog` behavior remains compatible.
