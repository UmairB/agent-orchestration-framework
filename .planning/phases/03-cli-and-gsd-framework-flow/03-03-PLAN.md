# Phase 3 Wave 3 Plan: Interactive Install Flow, Documentation, And Final Verification

## Goal

Add the guided `aof install --interactive` path, wire it to the config/render/framework planning behavior from Waves 1 and 2, document the finished CLI flow, and close Phase 3 with full verification.

## Requirements Covered

- **FRAM-01:** interactive flow can include managed GSD package intent.
- **FRAM-02:** interactive flow can preview/run Claude Code GSD setup.
- **FRAM-03:** interactive flow can preview/run Codex GSD setup.
- **CLI-01:** install/config/catalog inspection commands are documented and verified.
- **CLI-02:** user can use an interactive install-oriented flow.

## Decisions Covered

- **D-03:** human-readable output remains default.
- **D-04:** JSON output remains available where practical for previews.
- **D-16:** primary guided entry point is `aof install --interactive`.
- **D-17:** guided flow gathers selections, shows config/render/framework plan, then asks before writing `.aof/`, writing runtime files, or running GSD.
- **D-18:** interactive catalog selection stays simple in v1.
- **D-19:** existing `.aof/aof.config.json` is inspected and proposed additions/changes are shown before modifying.

## Implementation Tasks

1. Add confirmation prompt helpers.
   - Extend `src/prompt.mjs` with reusable yes/no confirmation prompts.
   - Add deterministic test hooks similar to existing selection hooks.
   - Keep prompts simple and terminal-oriented.

2. Implement `aof install --interactive`.
   - Reuse catalog seeding and item selection.
   - Reuse runtime selection.
   - Include a simple GSD choice through catalog selection or a direct confirmation.
   - Load existing `.aof/aof.config.json` when present.
   - Show proposed config additions or changes before writing.
   - Ask before modifying `.aof/`.
   - Ask before applying render actions to runtime folders.
   - Ask before running GSD installer commands.

3. Compose preview plans.
   - Reuse Wave 1 config diagnostics where useful.
   - Reuse Phase 2 render plan/action reporting for runtime file writes.
   - Reuse Wave 2 framework install planning for GSD command previews.
   - Keep dry-run and preview steps side-effect-free until confirmed.

4. Preserve existing non-interactive install behavior.
   - Ensure `aof install` without `--interactive` keeps the existing catalog UI/server behavior unless explicitly changed by Phase 3 work.
   - Ensure `aof install gsd` still uses the automation path from Wave 2.

5. Update docs and help.
   - Document `aof config show|validate|doctor`.
   - Document `aof install gsd --dry-run`, real installer boundary behavior, attempt recording, skip/force, and lock replay.
   - Document `aof install --interactive` as the simple guided setup path.

6. Add tests.
   - BDD scenarios for interactive new config creation with test-input hooks.
   - BDD scenarios for interactive existing config update preview and confirmation.
   - BDD scenarios showing the flow does not write `.aof/`, runtime files, or run GSD when the corresponding confirmation is declined.
   - Regression scenarios for non-interactive install, config commands, and GSD install preview after interactive changes.

7. Close Phase 3.
   - Run focused unit and BDD checks.
   - Update `README.md`.
   - Update `.planning/REQUIREMENTS.md` to mark FRAM-01, FRAM-02, FRAM-03, CLI-01, and CLI-02 complete if verified.
   - Update `.planning/ROADMAP.md` Phase 3 status to complete after execution verification, not during planning.
   - Write `.planning/phases/03-cli-and-gsd-framework-flow/03-VERIFICATION.md` during execution closure.

## Acceptance Criteria

- `aof install --interactive` guides users through item selection, runtimes, and GSD choice.
- The interactive flow shows proposed config, render, and framework plans before side effects.
- The interactive flow asks before writing `.aof/`, writing runtime files, and running GSD.
- Existing configs are inspected and proposed changes are shown before modification.
- Declining a confirmation prevents that side effect.
- Phase 3 docs and help describe the automation and interactive flows.
- Full Phase 3 test suite passes.
