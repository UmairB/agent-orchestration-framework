# Phase 14 Wave 2 Plan: Project Global Reference API And UI

## Objective

Add project `globalRefs` management to the setup UI and update the React interface so users can switch Project/Global scope, add global assets to the current project without copying, view referenced globals read-only, and remove references.

## Planning Assumptions

- Wave 1 provides scoped config loading and global asset save APIs.
- Project reference operations mutate only the current project config.
- Referenced global resources should be visible in project scope but not editable there.
- Global scope is where global source edits happen.

## Requirements Covered

- **GUI-01:** UI can switch between project asset editing and global asset editing.
- **GUI-03:** UI can add a global asset reference to the current project without copying the global asset.
- **GUI-04:** UI clearly labels asset source scope.

## Decisions Covered

- **D-01:** Top-level Project / Global toggle.
- **D-04:** Clear source-scope labels.
- **D-08..D-10:** “Use in this project” writes `globalRefs` without copying.
- **D-11..D-12:** Project view separates project-local and referenced global assets; referenced globals are read-only with remove-reference.
- **D-17..D-20:** Explicit project reference API and structured validation.

## Tasks

1. Add project reference editor helpers.
   - Load project `globalRefs` into editable project payloads.
   - Load referenced global resources into a read-only `referencedResources` or equivalent payload field.
   - Include reference state on global resources, such as `referencedByProject: true`.
   - Preserve diagnostics for missing refs and local/global conflicts.

2. Add reference API routes.
   - Add a project-only endpoint to add a global ref, for example `PUT /api/config/project/global-refs/:kind/:id`.
   - Add a project-only endpoint to remove a global ref, for example `DELETE /api/config/project/global-refs/:kind/:id`.
   - Make add idempotent for an existing identical reference.
   - Return structured diagnostics when a referenced global is missing, unsupported, or conflicts with a project-local asset.
   - Ensure no global source files are copied into project `.aof/assets`.

3. Update React state and data model.
   - Add `scope: "project" | "global"` UI state.
   - Fetch project and global payloads through explicit scoped endpoints.
   - Keep the first screen as the working editor.
   - Surface current config path and scope in the sidebar/header.

4. Add Project / Global UI.
   - Add a top-level segmented control or tabs for Project and Global.
   - In Project scope, show project-local editable assets and referenced global read-only assets separately.
   - In Global scope, show global assets and a “Use in this project” action when not already referenced.
   - Show “Referenced” state for globals already used by the project.
   - Add remove-reference action from Project scope referenced-global rows.

5. Add read-only referenced-global detail view.
   - Display referenced global metadata, body, runtimes, and source scope.
   - Prevent edits in Project scope for referenced globals.
   - Offer navigation/copy state to Global scope for editing the source asset.

6. Add tests.
   - Setup UI API can add and remove project `globalRefs`.
   - Add-reference does not copy global asset files into project `.aof`.
   - Referenced global resources appear in project payload as read-only/global.
   - Local/global conflict returns diagnostics.
   - UI build catches type and component integration issues.

7. Verify wave 2.
   - Run `npm run test:unit`.
   - Run `npm run ui:build`.

## Acceptance Criteria

- The UI has an explicit Project / Global switch.
- Users can add a global skill, agent, or rule reference to the current project.
- Adding a reference writes only project `globalRefs`.
- Project view clearly separates editable local assets from read-only referenced globals.
- Users can remove a global reference from the project.
