# Phase 14 Wave 3 Plan: Setup UI BDD Docs And Phase Hardening

## Objective

Prove the user-facing setup UI global asset workflow through BDD/API scenarios, document the setup UI global editing behavior, run full verification, and close out Phase 14 planning state.

## Planning Assumptions

- Wave 1 provides scoped setup UI APIs and global asset saves.
- Wave 2 provides project reference APIs and UI behavior.
- BDD coverage can exercise the HTTP setup UI API directly, matching existing setup UI BDD style.
- Visual browser automation is useful if the implementation has nontrivial UI risk, but API BDD and `ui:build` are the required baseline.

## Requirements Covered

- **GUI-01:** UI can switch between project and global editing.
- **GUI-02:** UI can create and edit global skills, agents, and rules.
- **GUI-03:** UI can add global asset references to the current project without copying.
- **GUI-04:** UI clearly labels asset source scope.

## Decisions Covered

- **D-01:** Project / Global toggle.
- **D-04:** Source-scope labels.
- **D-05:** Global skill, agent, and rule editing.
- **D-08:** “Use in this project” reference action.
- **D-10:** No source copies.
- **D-11..D-12:** Read-only referenced global assets in Project scope.
- **D-13:** Basic global skill associated-file editing.
- **D-17:** Explicit API scope.
- **D-19:** Structured diagnostics.

## Tasks

1. Add BDD scenario for scoped config loading.
   - Start setup UI server with isolated project and `AOF_GLOBAL_HOME`.
   - Request project scoped config.
   - Request global scoped config.
   - Assert payloads include `scope`, config path, and source labels.

2. Add BDD scenario for global asset creation.
   - Save a global skill through setup UI API.
   - Save a global agent or rule through setup UI API.
   - Assert global `aof.config.json` and body files are written under the global workspace.
   - Assert project `.aof/assets` remains unchanged.

3. Add BDD scenario for global skill associated files.
   - Save a global skill with `files: [{ path, body }]`.
   - Assert helper file exists under the global skill asset directory.
   - Assert global manifest includes the explicit `files` entry.
   - Assert unsafe helper paths return diagnostics.

4. Add BDD scenario for project references.
   - Save or precreate a global asset.
   - Add it to the current project through setup UI API.
   - Assert project config contains `globalRefs`.
   - Assert no global body/helper files were copied into project `.aof/assets`.
   - Remove the reference and assert it is removed from project config.

5. Add BDD/API scenario for read-only referenced globals.
   - Load project scoped config after adding a reference.
   - Assert referenced global appears in referenced/read-only payload.
   - Assert source scope is `global`.

6. Update README.
   - Document setup UI Project / Global scope switch.
   - Document global asset creation/editing in UI.
   - Document “Use in this project” reference behavior.
   - Document global skill associated-file editing scope and constraints.
   - Reiterate that UI edits config only; CLI runs apply/sync.

7. Run full Phase 14 verification.
   - Run `npm run test:unit`.
   - Run `npm run ui:build`.
   - Run `npm test`.

8. Update completion artifacts.
   - Write `.planning/phases/14-global-asset-setup-ui/14-03-SUMMARY.md`.
   - Write `.planning/phases/14-global-asset-setup-ui/14-VERIFICATION.md`.
   - Update roadmap, requirements traceability, project state, and project summary after execution.

## Acceptance Criteria

- BDD proves setup UI can load project and global scopes.
- BDD proves setup UI can create global assets.
- BDD proves setup UI can add/remove project references without copying global assets.
- BDD proves global skill associated-file editing is explicit and safe.
- README documents the user-facing workflow.
- Unit, UI build, and full BDD verification pass.

## Verification

- `npm run ui:build`
- `npm test`
