# Phase 18 Wave 1 Plan: Current Command Inventory

## Objective

Create a complete inventory of the current AOF CLI command surface and classify every command or subcommand as keep, move, replace, or remove under the v1.4 namespaced contract.

## Planning Assumptions

- This phase produces planning artifacts only. It does not change `src/cli.mjs` behavior.
- The inventory is the source checklist for later implementation phases.
- Removed commands have no legacy aliases, but later implementation may provide helpful failure text.

## Requirements Covered

- **CLI-01:** User can see a complete, documented command contract for every current and replacement AOF CLI command before the rewrite is implemented.
- **CLI-02:** User can rely on command names matching their side effects.
- **CLI-03:** User can run the rewritten CLI without legacy aliases for removed top-level commands.

## Decisions Covered

- **D-01..D-03:** `aof init` remains top-level; product work moves under namespaces.
- **D-29..D-32:** Full rewrite, removed top-level commands, remove sync, helpful failures only.

## Tasks

1. Enumerate current command routes.
   - Read `src/cli.mjs` command dispatch.
   - Include `init`, `add`, `apply`, `sync`, `clean`, `migrate`, `validate`, `doctor`, `install`, `global`, `catalog`, and `config`.
   - Include subcommands such as `global add/list/show/validate`, `config show/validate/doctor`, `install gsd`, `install --from-lock`, and `install --interactive`.

2. Capture current behavior.
   - For each command, record current purpose and notable side effects.
   - Record whether it writes `.aof`, renders runtime outputs, launches UI, executes package installer commands, touches catalog behavior, or only inspects state.
   - Record currently supported dry-run and JSON behavior where applicable.

3. Classify every command.
   - Use one of: `keep`, `move`, `replace`, or `remove`.
   - `aof init` should classify as `keep`.
   - Top-level asset/package/config/global/catalog commands should classify as `move`, `replace`, or `remove`, not `keep`.
   - `sync` should classify as `remove`.

4. Map each current command to the target command.
   - Map asset creation/render/validate/clean/UI behavior to `aof assets ...`.
   - Map GSD/package behavior to `aof packages ...`.
   - Map config/doctor/migrate behavior to `aof project ...`.
   - Mark catalog behavior as removed/deferred unless a later contract explicitly reintroduces it.

5. Write `.planning/phases/18-command-contract-audit/18-COMMAND-INVENTORY.md`.
   - Include a table with: current command, current purpose, side effects, classification, target command, notes.
   - Include a section for commands that must hard-fail in the rewrite.

## Acceptance Criteria

- Every command route in `src/cli.mjs` is listed.
- Every current subcommand visible in help text is listed.
- Every listed command has a classification and target behavior.
- `sync` is explicitly removed.
- No legacy alias is proposed.

## Verification

- Manually cross-check inventory against `src/cli.mjs` dispatch and `helpText()`.
- Confirm all current help text commands appear in the inventory.

## Completion Artifact

Write `.planning/phases/18-command-contract-audit/18-01-SUMMARY.md` with inventory count, removed command list, and any command ambiguity found.
