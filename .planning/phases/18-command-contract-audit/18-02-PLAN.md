# Phase 18 Wave 2 Plan: Replacement CLI Contract

## Objective

Write the accepted v1.4 CLI command contract in a form later implementation phases can execute without re-opening product decisions.

## Planning Assumptions

- The Phase 18 context already locks the command taxonomy.
- The contract document should be precise enough to become implementation and BDD guidance.
- The document should describe behavior, not implementation internals.

## Requirements Covered

- **CLI-01:** Complete documented command contract.
- **CLI-02:** Command names match side effects.
- **CLI-03:** No legacy aliases.
- **CLI-04:** Help output grouped by product area.

## Decisions Covered

- **D-01..D-28:** Top-level, project, assets, and packages namespace decisions.

## Tasks

1. Create the contract document.
   - Write `.planning/phases/18-command-contract-audit/18-CLI-CONTRACT.md`.
   - Use product-area sections: Top Level, Project, Assets, Packages, Removed Commands.

2. Define the top-level contract.
   - `aof init` remains top-level.
   - It creates only project `.aof` config/lock state.
   - It must not create assets, launch UI, render outputs, install packages, or initialize catalog storage.

3. Define the project namespace.
   - Document `aof project show`.
   - Document `aof project validate`.
   - Document `aof project doctor`.
   - Document `aof project migrate`.
   - For each command, include purpose, arguments, flags, writes, output, dry-run behavior, and errors.

4. Define the assets namespace.
   - Document `aof assets add skill|command|rule|agent [id]`.
   - Document `aof assets add --global skill|rule|agent [id]`.
   - Document list/show/remove/use/unuse/apply/validate/clean/ui.
   - Document partial interactive behavior, especially `aof assets add skill`.
   - Document runtime defaults and narrowing for `aof assets apply`.

5. Define the packages namespace.
   - Document `aof packages add gsd`.
   - Document list/show/remove/validate/install.
   - Document `aof packages install`, `aof packages install gsd`, and `aof packages install --from-lock`.
   - Document network/package-code boundary output and dry-run behavior.

6. Define removed command behavior.
   - List every removed top-level command.
   - State that removed commands do not execute and are not aliases.
   - Allow helpful failure messages that point to new commands.

## Acceptance Criteria

- Every command in the accepted draft command map is documented.
- Every command has purpose, arguments, side effects, missing-argument behavior, output, errors, and relevant dry-run behavior.
- The document states that `--global` is an assets scope flag.
- The document states that `sync` is removed.
- The document states that no install command launches the UI.
