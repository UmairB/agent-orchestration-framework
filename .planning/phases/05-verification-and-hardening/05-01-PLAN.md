# Phase 5 Wave 1 Plan: Config, Schema, Rendering, Lock, And Framework Regression Hardening

## Goal

Expand the automated safety net around the milestone's core CLI behavior: `.aof` config compatibility, strict core validation with extension tolerance, schema/model alignment, runtime override rendering, generated-output ownership, lock behavior, and managed GSD framework replay.

## Requirements Covered

- **VERI-01:** existing CLI behavior remains covered by unit and BDD integration tests.
- **VERI-02:** `.aof/` config parsing, rendering, runtime overrides, and lock state are covered by targeted tests.

## Decisions Covered

- **D-01:** run and preserve coverage for all milestone flows.
- **D-02:** add root plus `.aof` compatibility regressions.
- **D-05:** keep validation strict for invalid core fields and tolerant for extension fields.
- **D-06:** malformed JSON and unreadable file diagnostics are structured and blocking.
- **D-07:** root config compatibility is an explicit contract.
- **D-08:** schema alignment tests compare schema fields with the central model.
- **D-13:** cover create, update, skip, drift-warning, force overwrite, delete, and stale entries.
- **D-14:** add cross-kind runtime override coverage.
- **D-15:** cover framework attempt replay and failure paths.
- **D-16:** add selective golden checks for high-value outputs.

## Implementation Tasks

1. Harden config validation diagnostics.
   - Update `src/config-inspect.mjs` only where needed to distinguish malformed config JSON, unreadable config files, missing body files, malformed override JSON, and unreadable override files.
   - Preserve the existing diagnostic shape and add specific `code` values where practical.
   - Keep unknown extension fields on config, resources, overrides, and packages tolerated unless they conflict with core AOF fields.
   - Ensure `inspectConfig()` does not call `loadConfig()` when blocking validation errors exist.

2. Add root compatibility tests.
   - Add or expand tests for `findProjectConfig()` and config inspection.
   - Cover root-only legacy config as readable input.
   - Cover `.aof/aof.config.json` precedence when both configs exist.
   - Cover stale root warnings in doctor output.
   - Cover that migration/editor save paths write `.aof/aof.config.json` without silently mutating root `aof.config.json`.

3. Add schema/model alignment tests.
   - Add `test/schema.test.mjs` or extend `test/model.test.mjs`.
   - Parse `schemas/aof.schema.json` with Node's JSON parser.
   - Compare supported resource kinds and runtimes with `supportedResourceKinds()` and `supportedRuntimes()` from `src/model.mjs`.
   - Check that key config shape entries exist for `resources`, `packages`, `runtimes`, `overrides`, and rule-specific path fields.
   - Register the suite in `scripts/test-unit.mjs` and `scripts/test.mjs`.

4. Expand runtime override rendering coverage.
   - Add tests across skills, commands, agents, and rules where supported.
   - Verify shared defaults are used when no runtime override exists.
   - Verify Claude-specific and Codex-specific body/metadata overrides affect only the selected runtime output.
   - Verify override identity-field changes still fail.
   - Include a path-backed override file case, including malformed or unreadable override diagnostics from task 1.

5. Expand generated-output and lock matrix tests.
   - Extend `test/render-plan.test.mjs` or add a new focused suite.
   - Cover create, skip, update, drift-warning, force overwrite, stale delete, stale drift warning, and preserved drifted lock entries.
   - Verify the lock manifest records generated files, runtimes, framework intent, and preserved framework install attempts.
   - Add selective golden assertions for merged Codex `AGENTS.md`, Claude rule output, and lock manifest shape.

6. Expand framework install replay and failure coverage.
   - Extend `test/frameworks.test.mjs`.
   - Cover dry-run commands, success skip, force rerun, partial simulated failure, all-runtime success, lock replay, and runtime filtering.
   - Assert failure attempts include runtime, scope, package source, command, status, exit status, and skipped state.
   - Keep network execution out of tests by using `AOF_TEST_FRAMEWORK_INSTALL_STATUS`.

7. Preserve existing test harness behavior.
   - Register any new test arrays in both root harness scripts.
   - Keep `npm test` as unit plus in-process BDD integration.
   - Do not add UI build to `npm test`; that belongs to the Phase 5 check script work.

## Acceptance Criteria

- Config validation produces path-specific blocking diagnostics for malformed JSON and unreadable body/override files.
- Unknown extension fields remain tolerated.
- Root-only config, `.aof` precedence, and stale-root warnings are explicitly tested.
- Schema enums and high-value fields stay aligned with `src/model.mjs`.
- Runtime override rendering is covered across resource kinds.
- Generated-output ownership, drift, prune, force, and lock preservation paths are covered.
- Framework dry-run, skip, force, failure, and lock replay behavior is covered without network execution.
