# Phase 5 Wave 3 Plan: Child-Process Smoke, Final Regression Sweep, Documentation, And Verification Matrix

## Goal

Close the v1 milestone with real process-boundary smoke coverage, final regression verification, documentation updates, and a visible matrix mapping Phase 5 decisions and v1 requirements to automated tests and commands.

## Requirements Covered

- **VERI-01:** existing CLI behavior remains covered by unit and BDD integration tests.
- **VERI-02:** `.aof/` config parsing, rendering, runtime overrides, and lock state are covered by targeted tests.
- **VERI-03:** UI configuration editing paths are covered by build or targeted tests.

## Decisions Covered

- **D-01:** run and preserve coverage for all milestone flows.
- **D-03:** add focused child-process smoke tests.
- **D-04:** produce a visible final verification matrix.
- **D-10:** include browser smoke if feasible, with API/build fallback.
- **D-16:** include selective golden output checks in the final confidence set.
- **D-18:** keep `npm test` focused and `npm run check` as the broader closeout command.
- **D-19:** document build wrapper and direct fallback commands.
- **D-20:** run the full closeout command set.

## Implementation Tasks

1. Add focused child-process smoke coverage.
   - Add a small test script such as `test/integration/cli-child-process.test.mjs` or an equivalent harness entry.
   - Invoke `node bin/aof.mjs` in a temp project with isolated `AOF_DATA_DIR`.
   - Cover at minimum `--help`, a config or init command, and one dry-run/apply path that crosses the real process boundary.
   - Assert exit status, stdout/stderr expectations, and created file paths.
   - Keep this focused; do not duplicate the full BDD suite in child-process mode.

2. Wire child-process smoke into verification.
   - Add a named npm script such as `test:smoke:cli` if useful.
   - Decide whether `npm run check` includes this smoke script or whether it remains a documented closeout command. Prefer inclusion if runtime stays fast and deterministic.
   - Keep `npm test` unchanged as the focused unit/in-process integration command.

3. Run a milestone regression sweep.
   - Run `npm run test:unit`.
   - Run `npm test`.
   - Run the child-process smoke command if added outside `npm test`.
   - Run `npm run ui:build`.
   - Run `npm run check`.
   - If feasible, run `npm run test:integration:ps` as a Windows-specific compatibility check and record the outcome separately.

4. Verify execution boundary and generated-output boundaries.
   - Confirm setup UI APIs still do not execute `init`, `apply`, dry-run, `install`, shell commands, or framework installers.
   - Confirm setup UI config saves write `.aof/` source files only.
   - Confirm generated `.claude/` and `.codex/` output remains produced by CLI apply paths and tracked through the lock manifest.

5. Update documentation.
   - Update README test/check instructions for `npm run check`, `npm run ui:build`, and any child-process smoke script.
   - Document root config compatibility: root-only legacy input, `.aof` precedence when both exist, migration does not mutate root silently, and stale-root warnings.
   - Document setup UI local-only defensive posture and config-only execution boundary.
   - Document final verification expectations for maintainers.

6. Create the final verification matrix.
   - Write `.planning/phases/05-verification-and-hardening/05-VERIFICATION.md`.
   - Map requirements `VERI-01`, `VERI-02`, and `VERI-03` to tests/checks.
   - Map decisions D-01 through D-20 to the relevant automated tests, command checks, docs, or explicit residual-risk notes.
   - Include exact commands run and pass/fail/skipped status.
   - Include environment notes for any browser or PowerShell smoke limitations.

7. Create the final Phase 5 summary.
   - Write `.planning/phases/05-verification-and-hardening/05-03-SUMMARY.md`.
   - Summarize child-process smoke, final regression sweep, docs, verification matrix, and any deferred risks.
   - Note if `STATE.md` or `ROADMAP.md` remain stale because local `gsd-sdk query` mutation handlers are unavailable.

## Acceptance Criteria

- A real child-process CLI smoke test exists and passes, or a documented blocker explains why it could not be added.
- The final closeout command set has been run and recorded.
- `npm run check` includes the broader verification set selected in Phase 5.
- README reflects compatibility, build, setup UI, and verification behavior.
- `05-VERIFICATION.md` maps requirements and Phase 5 decisions to concrete evidence.
- Phase 5 produces summaries for all plans.

## Verification

- `npm run test:unit`
- `npm test`
- child-process smoke command, if separate
- `npm run ui:build`
- `npm run check`
- `npm run test:integration:ps` if feasible

Write `.planning/phases/05-verification-and-hardening/05-03-SUMMARY.md` and `.planning/phases/05-verification-and-hardening/05-VERIFICATION.md` with final matrix, command results, documentation updates, and residual risk.
