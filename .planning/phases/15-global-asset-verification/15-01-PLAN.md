# Phase 15 Wave 1 Plan: Global Asset Coverage Audit

## Objective

Create a requirement-to-evidence coverage matrix for the full v1.2 global asset milestone and add only targeted tests for any concrete coverage gaps.

## Planning Assumptions

- Phases 11 through 14 already shipped the product behavior.
- Phase 15 should not add features.
- Existing unit and BDD tests are likely close to sufficient, but the audit must prove that explicitly.
- Any added tests should be tightly scoped to missing global asset coverage.

## Requirements Covered

- **TEST-01:** Unit tests cover global library path resolution, reference resolution, conflict handling, associated files, and lock metadata.
- **TEST-02:** BDD integration tests cover CLI global asset creation, project reference rendering, missing-reference diagnostics, and UI API behavior.
- **TEST-03:** UI build passes after global asset management changes.

## Decisions Covered

- **D-01..D-03:** Full v1.2 verification scope and CLI/UI coverage.
- **D-08:** Create a coverage matrix.
- **D-09..D-10:** Add tests only for real gaps.
- **D-11..D-13:** Avoid feature expansion and preserve behavior.

## Tasks

1. Build the coverage matrix.
   - Create `.planning/phases/15-global-asset-verification/15-COVERAGE.md`.
   - Map every v1.2 requirement from GLIB-01 through TEST-03 to evidence.
   - Include evidence categories: unit, BDD, setup UI API, UI build, PowerShell parity.
   - Mark each requirement `covered`, `partial`, or `missing`.

2. Audit unit coverage.
   - Check `test/paths.test.mjs` for global workspace path and override coverage.
   - Check `test/config-inspect.test.mjs` for global validation, referenced globals, missing refs, conflicts, associated files.
   - Check `test/render-plan.test.mjs` for global lock source scope, associated files, drift, and conflict behavior.
   - Check `test/setup-ui.test.mjs` for global setup UI APIs and project reference APIs.

3. Audit BDD coverage.
   - Check lifecycle scenarios for global add/list/show/validate, referenced global rendering, sync, missing refs, conflicts, associated helper files, and unsafe files.
   - Check setup UI scenarios for scoped loading, global creation, associated-file editing, and project reference add/remove.

4. Add targeted tests if needed.
   - Add only tests required to move `partial` or `missing` rows to `covered`.
   - Prefer BDD for user-facing gaps and unit tests for edge-case semantics.
   - Do not add broad refactors or new product behavior.

5. Verify wave 1.
   - Run `npm run test:unit`.
   - Run `npm test` if BDD scenarios changed.

## Acceptance Criteria

- `15-COVERAGE.md` maps all 22 v1.2 requirements to exact evidence.
- `TEST-01`, `TEST-02`, and `TEST-03` have explicit evidence rows.
- Any missing or partial coverage has either a targeted test added or a clearly documented residual risk.
- No new feature scope is introduced.

## Verification

- `npm run test:unit`
- `npm test` if BDD changes

## Completion Artifact

Write `.planning/phases/15-global-asset-verification/15-01-SUMMARY.md` with audit result, tests added, remaining risks, and the command results.
