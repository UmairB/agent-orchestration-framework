# Phase 15 Wave 2 Plan: Cross-Runner Verification And Hardening

## Objective

Run the full required verification command set, fix any concrete global-asset regressions or runner parity defects, and capture command evidence for milestone closeout.

## Planning Assumptions

- Wave 1 identifies any test gaps and adds targeted coverage if needed.
- This wave is expected to be mostly command execution and issue triage.
- On Windows, PowerShell integration parity is required.

## Requirements Covered

- **TEST-01:** Unit tests pass after global asset hardening.
- **TEST-02:** BDD integration tests pass through Node and PowerShell runners.
- **TEST-03:** UI build passes after global asset management changes.

## Decisions Covered

- **D-04:** Run `npm run test:unit`.
- **D-05:** Run `npm run ui:build`.
- **D-06:** Run `npm test`.
- **D-07:** Run `npm run test:integration:ps` on Windows.
- **D-11..D-12:** Add code only for concrete defects.
- **D-14..D-15:** PowerShell parity is required unless blocked by outside constraints.

## Tasks

1. Run required commands.
   - `npm run test:unit`
   - `npm run ui:build`
   - `npm test`
   - `npm run test:integration:ps`

2. Triage failures.
   - If unit or Node BDD fails, fix the behavior or test fixture causing the failure.
   - If `ui:build` fails, fix TypeScript/build errors without changing product scope.
   - If PowerShell integration fails, determine whether it is a runner parity issue, fixture issue, path quoting issue, or real CLI defect.

3. Preserve shared BDD semantics.
   - Ensure Node and PowerShell runners consume the same feature files.
   - Avoid creating PowerShell-only scenario drift.
   - If a feature step is unsupported in PowerShell, add parity support or document a justified blocker.

4. Re-run failed checks.
   - Repeat only failed commands until clean.
   - Run the full command set once after fixes.

5. Record command evidence.
   - Capture pass/fail status and any notes for `15-VERIFICATION.md`.
   - Note platform and date for PowerShell parity.

## Acceptance Criteria

- All required commands pass, including PowerShell integration on Windows.
- Any code changes are tied to concrete verification failures.
- Node and PowerShell integration behavior remains aligned on shared feature files.
- Command evidence is ready for final verification artifact.
