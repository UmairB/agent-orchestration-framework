# Project Retrospective

*A living document updated after each milestone. Lessons feed forward into future planning.*

## Milestone: v1 — Assistant Configuration Foundation

**Shipped:** 2026-05-07
**Phases:** 5 | **Plans:** 15

### What Was Built

- Repo-local `.aof/` workspace ownership for config, assets, runtime overrides, and lock state.
- Claude Code and Codex render adapters with dry-run planning, drift protection, stale pruning, deterministic rule merging, and framework lock intent.
- CLI flows for init, migrate, apply, inspect, doctor, catalog install, GSD install planning/execution, lock replay, and guided interactive setup.
- Setup UI configuration editor for `.aof` resources, runtime targets, runtime-specific overrides, capability visibility, validation, and review.
- Regression hardening across unit tests, BDD integration tests, child-process CLI smoke, PowerShell smoke, setup UI API tests, and UI build.

### What Worked

- Keeping `.aof/` as the source-of-truth boundary simplified rendering, UI editing, and lock-state decisions.
- BDD scenarios stayed useful as product-level regression coverage while unit tests covered model, adapter, lock, and API details.
- Explicit runtime capability modeling prevented Claude/Codex differences from leaking into ad hoc UI or adapter branches.

### What Was Inefficient

- Planning state updates lagged behind implementation when local GSD query/mutation handlers were unavailable.
- Some closeout evidence had to be reconciled manually from phase artifacts instead of being generated by the SDK workflow.

### Patterns Established

- Real apply and dry-run share action-plan analysis before side effects.
- Runtime overrides merge only allowed metadata/body fields and cannot change resource identity.
- Setup UI writes valid config and leaves execution to the CLI.
- Generated runtime folders are protected by lock state and never treated as source of truth.

### Key Lessons

1. Commit the implementation before milestone tagging; otherwise the archive tag can point at documentation without shipped code.
2. Keep closeout labels tied to product blockers. Missing optional process artifacts should be process notes, not tech debt.
3. Central runtime/resource metadata pays off across schema validation, rendering, setup UI capability display, and tests.

### Cost Observations

- Sessions: multiple phase-oriented GSD sessions.
- Notable: Inline execution was necessary where GSD subagents or SDK query handlers were unavailable.
